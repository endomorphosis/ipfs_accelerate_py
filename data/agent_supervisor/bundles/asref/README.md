# ASREF objective bundles (`asref/*`)

Multi-lane execution surface for the **Agent Supervisor Module Refactor** program
(prefix `ASREF`, goal root `ASREF-G000`, autonomous-execution goal `ASREF-G100`).

This directory is the repo-local `--objective-bundle-dir` used by the objective
daemon and multi-lane implementation supervisors. It is the durable hand-seeded
layout; large `index.json` / `todo_vector_index.json` files may be regenerated by
objective scans and should not be hand-edited as sources of truth.

## Authoritative program documents (protected)

These three files are **operator-protected**. Launch scripts always fence them
with `--implementation-protected-path`. Never list them as editable task Outputs.

| Path | Role |
|---|---|
| `docs/architecture/agent_supervisor_module_refactor.objectives.md` | Objective heap |
| `docs/architecture/agent_supervisor_module_refactor.todo.md` | Todo board (drainable projection) |
| `docs/architecture/AGENT_SUPERVISOR_MODULE_REFACTOR_PLAN.md` | Human plan, lane matrix, no-shim rule |

ASREF-G100 evidence coverage for the plan and todo board is recorded in
[`evidence_coverage_asref_g100.md`](./evidence_coverage_asref_g100.md).

## Exact multi-lane launch commands

Prefer the ops launcher (prints preflight JSON and emits protected-path flags):

```bash
# From the repo root (or ASREF worktree) on branch refactor/agent-supervisor-layout

# 0) Preflight: heap, board, protected paths, open tasks
python scripts/ops/agent_supervisor/asref_multi_lane.py preflight

# 1) Refine broad goals into children if needed
python scripts/ops/agent_supervisor/asref_multi_lane.py objective-scan --refine-objective-heap

# 2) Generate / refresh todos from missing evidence into the board + this bundle dir
python scripts/ops/agent_supervisor/asref_multi_lane.py objective-scan

# 3) Dry-run multi-lane implementation argv (Grok as provider)
python scripts/ops/agent_supervisor/asref_multi_lane.py launch \
  --implementation-provider grok \
  --dry-run

# 4) Start multi-lane drain with objective refill
python scripts/ops/agent_supervisor/asref_multi_lane.py launch \
  --implementation-provider grok \
  --enable-objective-refill
```

Equivalent console entry shape (from the plan):

```bash
ipfs-accelerate-agent-objective-daemon \
  --objective-path docs/architecture/agent_supervisor_module_refactor.objectives.md \
  --todo-path docs/architecture/agent_supervisor_module_refactor.todo.md \
  --discovery-dir data/agent_supervisor/discovery/asref \
  --objective-bundle-dir data/agent_supervisor/bundles/asref

ipfs-accelerate-agent-bundle-supervisor \
  --objective-bundle-dir data/agent_supervisor/bundles/asref \
  --start
```

## Provider selection (Grok 4.6 / successor)

Provider is **not** encoded in goal text or package structure. Select at launch:

```bash
export IPFS_ACCELERATE_AGENT_IMPLEMENTATION_PROVIDER=grok
# aliases accepted by the daemon: grok, grok_cli, grok-cli, xai_cli, grok_build, ...
# other values: auto | goose | codex | copilot
# full override: IMPLEMENTATION_DAEMON_COMMAND='...'
```

Provider bridges belong under **integrations/runtime**. Package-move tasks must
not block on provider choice.

## Invariants for workers

1. Honor each task `Validation:` line before completion.
2. **No shims** at retired flat `agent_supervisor/*.py` paths.
3. Stay inside the task `Bundle` / `Conflict policy` ownership set.
4. Prefer one package move per task after the freeze map exists.
5. Do not edit the three protected architecture files.
