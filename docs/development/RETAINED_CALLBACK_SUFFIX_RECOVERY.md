# Retained callback suffix recovery

A historical receiver key failure can be followed by an erroneous generic retry,
an admitted dependency preflight deferral, and a second admitted attempt stopped
by the retained-seed guard. The completed merge request belongs to the original
attempt. It must not become permission to run another provider.

`retained_callback_suffix.py` recognizes exactly that eight-revision sequence.
It requires unchanged task semantics and route policy, complete canonical
history, exact claim-to-admission overlays, consecutive distinct claim/fence
identities, the original receiver failure, and the reserved pre-dispatch denial.
The daemon separately reproduces all three failed physical attempts and phase
histories. The intervening deferral needs its typed no-provider fingerprint;
the final denial must occur at the seed guard before projection/provider setup.
Legacy `unknown` fields remain unchanged in historical evidence. They are not
rewritten as successful validation or provider results.

Discovery feeds the original completed request into the existing Portal
callback reconciliation. Its source binding, candidate ancestry, integration
receipt and fresh validation on the current target remain mandatory. The
existing V2 seed records separate original and current control revisions. Only
the latest expired claim authorizes the atomic queue/CAS; original claims remain
historical provenance. The complete suffix is checked again inside that guard.
The native claim/admission verifier and replay verifier reproduce the same
suffix before accepting the retained seed. The bridge's early seed guard and
ordinary retry exclusion remain in force.

The fixture preserves the relevant native revision and execution shapes with a
minimal task body. Tests cover foreign identity and route changes, gaps, unknown
fields, active attempts/fences, prepared completions, phase drift, and the actual
`run_provider` routing boundary. Existing real DuckDB CAS and Portal candidate
qualification tests remain separate. No history fixture grants live authority.
