# Worker argument identity

A process listing provides diagnostic `ps` text and exact procfs argument boundaries. Worker recognition now prefers available exact arguments so empty or truncated display text does not hide an active provider during source reload or daemon termination. A conflicting display cannot override the exact executable, module or script positions. Python inline commands and malformed argument records remain unrecognized. Empty downstream prompt/option values and ordinary bundled Python flags are preserved.

Recognition is custody evidence, not task completion or retry authority. This native runtime retains its existing ordinary-provider receipt check whenever an exact implementation attempt is active, together with sealed-runner checks. Source drift remains pending even when Git HEAD and its committed tree are unchanged: dirty source bytes are part of the loaded generation identity.

Focused regressions exercise idle authenticated projections, the actual reload and termination paths, missing receipts, argument ambiguity and procfs decoding. No task aliases, cross-lane JSON guesses, direct status changes, or source identity suppression are introduced. The live PCTDD source and current owner still require independent qualification before adoption.
