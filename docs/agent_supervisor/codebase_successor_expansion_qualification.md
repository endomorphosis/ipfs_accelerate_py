# Complete successor scans and device inference

This increment qualifies a fresh complete CPU 8D successor scan, signed native
successor dispatch and bounded CUDA inference for LegalIR. These are partial
production gates; all 32 acceptance
tasks in the [implementation backlog](../architecture/repository_proof_index_and_codebase_ir.todo.md)
remain open. Historical reports retain their original source and archive pins.

The complete scan starts from the independently checked
[source/model successor setup](codebase_source_successor_qualification.md),
copies its source and model stores, and changes only the two copied stores'
local artifact paths. Training stays an explicit caller action. Resuming and
receiving a completed scan never train or promote a model.

## Shared resource ownership

The scan, native receiving and CUDA jobs attach to one
[persisted host configuration](../../../../artifacts/codebase_ir_terminal_bench/successor-expansion-resources-20261003-01/configuration.json).
GB10 CPU and GPU memory share physical RAM, so their reservations charge one
conservative shared memory envelope. Other owners' processes are preserved.
The signed worker uses an actual CPU/RAM/PID Docker cgroup beneath a held host
reservation. Its local accounting state is separate because container PIDs
cannot safely be interpreted as host PIDs; it does not create an independent
whole-host resource pool.

## Remaining profile and worker gates

General CodebaseIR384 and CUDA structural-feature inference need separate
qualification. Existing CodebaseIR profiles use CPU float64 structural features
and latent widths 1–64. Their lineage records pin the producer implementation;
adding a branch to those shared files would invalidate the current lineage.
The next bounded CUDA step is a separate read-only device session over received
immutable CPU state, with CPU opt-out, actual tensor-forward evidence, declared
numeric tolerances, checkpoint/Adam byte preservation and final source/model
fences. The 384D step requires a declared source-conditioned profile, codec,
architecture and migration path rather than changing the existing width limit.

Larger capture profiles, distributed signed workers, automatic crash recovery,
cross-shard proof closure and independently checked source/intent correspondence
remain open. The [machine review](../architecture/repository_proof_index_and_codebase_ir.successor_expansion_review.json)
records these bounded gates and preserved failures; it changes none of the 32
production acceptance rows.
