# Context projection pair evidence — 2026-10-13

This bundle retains the completed offline Docker comparison of the existing
`legacy` and `common-bindings@1` metadata presentations, with `identity@1` source
reading in both arms. It also retains preparation records for a separate native
Grok comparison. The Grok baseline stopped at credential readiness without a
reward; its projected arm was prepared but not executed. A separately declared
Codex GPT-6.1 sol fallback pair completed with 313,979 versus 313,980 native
tokens and rewards 0 versus 1. This one pair establishes no token reduction or
causal success advantage. The offline result below is a separate byte
measurement, not a native token score.

| One-pass captured UTF-8 bytes | Legacy | Common bindings |
| --- | ---: | ---: |
| Complete prepared router prompt | 53,933 | 53,048 |
| Default source/catalog CLI stdout, including newlines | 25,429 | 25,429 |
| CLI stderr | 0 | 0 |
| Prompt plus CLI text, counted once | 79,362 | 78,477 |

The difference is **885 bytes, or 1.12%** of the scripted exposure. Both arms made
12 CLI calls, applied the same authored public-source rename, and restored the
workspace. The shared metadata table removes 1,840 bytes of repeated capsule and
admission fields and adds 955 bytes of table, instructions and representation
wrappers. The production codec reconstructs the original semantic transport
exactly; this is lossless metadata factoring, without a program-equivalence
proof or newly granted source-omission authority.

The offline baseline already deferred the complete raw `eigen.py` and `eval.py` program
sources. Its inline `raw_sources` contained the instruction, structural smoke
check and task profile. All three support values, the selected capsule content,
native task context, source-reader guidance and response contract are preserved.
The initial [investigation](investigation/design.json) identified this fact; its
proposed raw-source substitution fixture was not implemented.

The treatment used **one more total token**: 198 fewer input tokens and 199 more
output tokens. Complete native usage is reported; billing totals are not
independently verified. The baseline passed correctness checks but failed one

cannot establish that metadata factoring caused the different reward, and these
are supervisor arms, not a new comparison against the native Codex harness.
The [exact control audit](native-codex/final/exact-control-audit.json) confirms
the intentional configuration differences are metadata presentation and output
location. Planning and provider sessions were independently generated. Native
candidate output hashes were unavailable, so output byte identity is unknown.

In the projected native arm, the codec replaced its own 68,006-byte coding input
with 67,124 bytes, an **882-byte within-arm reduction**. That measurement is
separate from the **885-byte** authored offline result. Native planning outputs
and trajectories can differ between arms, so neither prompt difference alone
predicts whole-session tokens.

Both native runs recorded zero source-broker requests. IntentIR reported
`fail_open_no_checkpoint`; Source384 reported four decoded candidates, all
unverified with unsupported source contracts, and no verified formalization for
those four units. These results do not establish learned IntentIR planning,
proof-guided source omission or an indexed-reader token advantage. The run covers
one task with two Codex attempts and one failed Grok setup attempt, not the full
Terminal-Bench suite.
