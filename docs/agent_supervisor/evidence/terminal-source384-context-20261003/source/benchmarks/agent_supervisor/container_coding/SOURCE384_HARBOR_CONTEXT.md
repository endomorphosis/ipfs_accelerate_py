# Source384 repository context for the isolated Harbor profile

The opt-in full arm now consumes the pinned shared SecurityIR384 checkpoint
through datasets' source-unit inference owner before goal planning. The
controller signs the permitted source population first. Preparation builds a
native DuckDB AST/source catalog and immutable source artifacts in private trial
state, inventories exact complete Python functions, and runs offline GTE-small
and the shared decoder in a bounded CPU subprocess. It never trains, downloads,
promotes a checkpoint, or adds authored functions to the benchmark repository.

Use the explicit configuration and common resources described in
[SOURCE384_HARBOR_ASSETS.md](SOURCE384_HARBOR_ASSETS.md). All comparison arms must
select the same `source384-5cpu-8gib@1` resource profile. The original task limits
remain the default. A selected Source384 profile excludes legacy Security
training and inference selections; the no-index arm records Source384 disabled.

The source owner captures the signed inventory, including the supervisor's
dot-prefixed public inputs. Native scanner exclusions have explicit dispositions.
Inference selects the first 128 AST-equivalent functions in canonical path/byte
order from a complete inventory bounded at 1,024 functions. Functions above the
512-token embedding limit are deferred; unselected, unsupported and failed
predictions remain visible. Function spans retain their enclosing source
identity and normalization map. They do not establish whole-file semantics.

Planning receives a bounded summary with model/source identities, complete
coverage counts, candidate samples and omission counts. The full native result
is retained separately. Samples carry the complete typed IR as bounded canonical
JSON text, preserving the planner's nesting limit. Vectors and full source maps
remain in the native artifact; their candidate and source-map hashes bind the
summary to that artifact. Initial-context, planning, admission, START and worker
dispatch reload the selected source/model receipt. Replays check source heads,
active AST rows, exact source bytes, immutable model version, checkpoint and GTE
assets, producer identities, inference artifact and intended population. They
perform no neural inference or refit. Context substitution during planning is
rejected even if the substituted artifacts would independently validate.

Learned candidates carry no proof, formalization, execution or completion
authority. The existing independently reviewed Doctor/validation contracts
remain necessary. Repository-specific retention is `not_evaluated`.

After accepted publication, the initial receipt is historical. Completed work
and STOP remain observable; a subsequent dispatch still requires current
evidence. This profile reports `successor_unavailable` until a new Source384
generation is prepared. It does not silently downgrade the selected task bundle
to an unindexed bundle. See
[SOURCE384_TASK_CONTEXT_FENCES.md](../../../docs/agent_supervisor/SOURCE384_TASK_CONTEXT_FENCES.md).

## Qualification boundaries

Tests use actual pinned checkpoint/GTE inference with an authored provider
response to verify delivery through planning and the canonical dispatch loader.
Separate native lifecycle tests exercise publication, completion and STOP; their
Source384 observation fixture is explicitly authored. These are different
qualification populations and are not a completed Harbor benchmark run.

The retained original Bottle-source canary is tracked separately from the
official task. Its first native preparation attempt exhausted the unchanged
90-second phase budget during repeated index observation. Bottle's 4,652
dependency edges exceeded the 4,096-entry CID memo working set. Increasing the
bounded pure encoding/validation caches to 8,192 entries retained all integrity
checks and reduced profiled observation from 27.85 to 13.62 seconds. The failed
attempt remains in the evidence.

The corrected canary prepared the full initial indexed context in 156.91
seconds, including 58.16 seconds for Source384 capture/inference, 64.47 seconds
for semantic construction/reconstruction/hydration and 16.62 seconds for final
evidence replay. Its complete 358-function inventory contains 127 decoded
candidates, one token-limit deferral, 166 selection-budget deferrals and 64
normalization refusals. Two complete typed IR samples reach the bounded summary;
125 additional candidates are explicitly omitted from that sample. Every decoded candidate is unsupported by the current
source-contract grammar. There are zero newly source-qualified or proved
properties, training steps or text-provider calls. The retained source matches
the earlier public-image observation; this is not a fresh Docker task trial.
No new Terminal Bench score, token savings or learned-proof advantage is
established. Cold preparation cost remains material within the 300-second
outer task limit.

The first summary included embedding vectors and consequently omitted every
candidate by size. Removing those vectors exposed the planner's existing nested
object limit. Canonical IR JSON text fixes both delivery failures without
increasing the planner limits. A subsequent review moved preparation's deadline
start ahead of source reads and producer hashing; the larger retained-source
canary above predates that timer-only correction. Final checkpoint tests cover
the corrected deadline and complete IR delivery.

Remaining work includes a qualified successor-generation lifecycle, source
semantics and decoder coverage for Bottle's string/header behavior, the combined
resource-pressure matrix, and fresh matched native Codex/no-index/full Harbor
trials. Existing broader backlog criteria retain their current status.
