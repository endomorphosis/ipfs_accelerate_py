# Frozen benchmark shared source policy — 2026-10-13

This phase connects an explicit `SourceViewPolicy` recipe to benchmark
preparation, the Harbor agent, coding owner and source-session collection.
It reuses the existing codec, source broker, admitted scope and shared
protocol. No model/checkpoint/embedding asset or database owner is changed.

## Scope

Preparation accepts one closed, bounded JSON recipe and detaches it into the
configuration and preparation receipt. Configuration controls cover it;
separate SHA-256 values retain canonical recipe and resolver/codec identity.
Execute rejects changed selection or a retained-controls downgrade before
subprocess calls. Agent setup/run recheck the frozen selection. A public file
may be supplied only during preparation; execute/collect do not re-read it.

The owner consumes `--source-view-policy-json` before launching the coding
worker. The worker receives the shared descriptor, whose policy identity is
joined to the frozen report by the collector. Discovery, baseline/working
reads and exact expansion reuse the existing shared protocol. Legacy absent
selections preserve their shapes. Unknown/malformed recipes, duplicate JSON
keys, conflicting profiles, disabled selection and nonfull arms refuse.
Collection of absent, foreign, downgraded or incomplete sessions remains
unavailable rather than an invented zero.

## Limits

The real semantic producer, Git worktree, sealed prompt and source projections
are exercised with authored UID/launch seams. They do not qualify a new Docker
or cross-UID container boundary. Benchmark subprocesses and environment methods
in preparation/agent tests are authored seams; no live Harbor task, model,
provider, training, checkpoint inference, solver or official task verifier runs.

A policy selects display behavior only. It does not broaden the existing
64-file/1-MiB admission, add new repository paths, refresh accepted proofs, or
provide a filesystem export. Finite proof-query signed invocations combined
with policy JSON remain unsupported and are refused by the existing exact
command guard. A separately qualified signed owner-to-worker transformation
would be required to support that combination.

Policy resolver bytes changed to add serialization. Rebuild the runtime archive
against current capability hashes, and regenerate affected shared-policy
admissions/numerical receipts/candidate caches when their producer pins change.
Codec/restoration and pure compact-edit mapper bytes are retained unchanged.
No complete-session token reduction, task advantage or autoformalization
quality gain is established by this plumbing increment.
