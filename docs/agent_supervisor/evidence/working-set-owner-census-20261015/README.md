## Lifecycle and inference evidence

The run used the full indexed arm, signed `declared-contract@1` planning,
original semantic transport, legacy metadata, identity source views and
`capsule-references@1`. Source384 consumed its pinned local checkpoint during
preparation: inference took 9.744 seconds and its checkpoint, configuration and
inference digests match the owner's currentness observation. This establishes
that inference ran; it does not establish semantic correctness of its outputs.

Initial context took 14.634 seconds, declared planning 4.478 seconds, admitted
context 3.704 seconds and the census 29.572 seconds. These are nested within
the 491.373-second owned Docker lifecycle; inference is also inside initial
context. Deployment time is included in that lifecycle. These are single-run
observations, not comparative throughput results.

The ordinary qualified worker and source broker were used. The selected route
made one authenticated preflight request: 4,096 response bytes, including 2,327
evidence bytes, and zero bytes supplied to a provider. It did not verify complete
capsule expansion. The owner independently replayed both complete inputs and the
closed observation, verified the retained declared planning receipt, checked
current source/admission after return and removed the allocated worktree.
The source session stopped with complete accounting; worker cleanup returned
zero; the exact Docker container was confirmed absent twice.

Two authored test fixtures were corrected between completed batches; all

[The manifest](manifest.json) binds all 23 retained evidence files. The frozen
runtime archive was checked against 27,551 member records before execution;
source, dependency, asset and launcher pins were unchanged at final cleanup.
Only closed observations, qualification records and hashes are retained here;
raw prompts, private owner archives and provider transcripts are excluded.

The next optimization should target the measured evidence/pack representation
with an exact inverse, preserve required constraints and unknown fields, and
account for any later retrieval. The 81-byte result alone does not justify an
efficiency claim or another expensive coding comparison.
