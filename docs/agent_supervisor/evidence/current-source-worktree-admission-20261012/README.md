# Native source worktree admission qualification, 2026-10-12

The owner-private allocation guard joins an existing native task admission to
its genuine database-to-Portal projection, active managed-worktree lifecycle
record and exact task index. It verifies the separate native and Portal task
identities, encoded attempt, lane/state directory, daemon kernel birth and
registered linked Git checkout. Same-owned lease renewal is allowed only with
monotonic fence/update/expiry and fixed ownership fields.

All **118 distinct host tests passed**, with zero failures, errors or skips:
31 new allocation cases, five native lifecycle controls and 82 retained native
task/source/typed-owner cases. Normal pytest plugins and separate collection/
execution AST seals remained enabled. All 37 recorded direct source/test bindings
stayed identical. This first run passed; no corrective rerun was needed.

The fixture follows actual lifecycle order: native claim and sealed Portal
projection, `begin_preparing`, Git worktree creation and `mark_active`. It uses
real DuckDB, typed Unix grants/requests, native task receipts and claims,
retained source CAS, Portal projection and lifecycle/index/Git files. Quack
listener capability/lifecycle and deployment metadata are authored seams. The
native daemon object executes in the test owner's process; no separate daemon
child, live supervisor START or coding-worker UID is exercised by this phase.

The owner explicitly protects its existing control/Portal/Git authority paths
before capture. The guard does not chmod, create an allocation or repair a
lifecycle record. Bound read facades use the original database connection with
schema installation disabled. Native claim fencing retains its normal metadata,
event and expiry-handling effects, including its existing metadata-repair
limitation. This is not a zero-write observer or pre-repair integrity proof.

An allocation-marked source reader requires the same private allocation and
task handles in the optional broker. Serialized snapshots are inert. The
existing task binder lock covers the empty-reader precondition, publication and
allocation marker attachment; a refused second bind cannot adopt or remark an
existing reader. A late failure can retain a consumed publication and the
original owner's cleanup responsibility. No rollback or rebind is inferred.

Immutable complete Portal projection/binding and Git controls retain physical
and byte identities. Lifecycle/index files may be individually replaced by a
coherent same-owned renewal; they are not an atomic pair. Concurrent renewal can
refuse a sequential observation. There is no filesystem writer lease or atomic
transaction across task claims, source bytes and allocation records.

Backend successful envelope bytes remain charged before a later guard can
refuse publication. The closing claim/allocation check follows CAS replay and
precedes closing full source checks. Handshake/error/partial transport and
provider usage remain unknown. This phase makes no token-saving, official reward,
formal-proof or semantic-reconstruction claim.

The first allocation profile requires a canonical checkout with an actual
`.git` directory and a distinct registered linked workspace. Bare roots and a
linked canonical checkout are unsupported. Host repository/root/merge-target/
board policy and source CAS/inventory/context provisioning remain explicit.
Runtime bootstrap receipts, compiled context, remote actual-child acknowledgment,
ordinary single-lane serialized coordination and native restart/source rebind
remain production integration requirements. The daemon is not a substitute for
the actual coding child.

The parallel working-source and candidate capsule/pending-formula refreshes are
preserved with their separate unverified semantics. Accepted proof/index
publication, mapped edits and complete planned provider-session comparisons
remain separately qualified work. Existing LegalIR, SecurityIR, CodebaseIR and
IntentIR assets, embeddings and family/schema/task/8D/384D/768D checkpoints are
unchanged. This phase runs no encoder, decoder, provider or prover and does not execute
the admitted fixture repository source.

Public artifacts contain source, commands, test results, hashes and bounded
reviews. Private database/CAS contents, credentials, model states and pytest
