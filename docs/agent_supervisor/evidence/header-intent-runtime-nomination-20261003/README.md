# Runtime-captured header applicability for symbolic intent planning

The actual checkout passes **354 distinct tests**: 83 native intent/planner cases,
114 transport/orchestration cases, 96 admission/context regressions and 61 datasets
cases. The initial datasets run has 60 passes and one explicit-public-input skip;
the separately recorded public-input case passes with its exact permitted source
hash. No failure or skip is converted into a pass count.

The end-to-end case starts with independently authored Python and a reviewed
instruction mapping. Ordinary preparation signs the static selector before any
index exists. Initial context consumes the real SecurityIR Source384 checkpoint
and pinned GTE snapshot, constructs the native DuckDB/CAS index, and captures the
source-bound header model. A runtime nomination binds that capture to the signed
manifest, source, model configuration and selected checker. The actual bounded
Z3 adapter supplies an operation precondition; the symbolic planner admits two
goals and one task, and the admitted worker-context loader revalidates the exact
selection. One model load is asserted and subsequent neural inference is forbidden
by the test. No planner provider is called. No repair or task completion occurs.

The six checked SMT obligations describe recognized header helpers under explicit
reviewed WSGI and ordinary-string premises. Learned candidates remain unverified.
The new fact says that a reviewed guard has a local-model counterexample; it is
not the desired security goal and grants no mutation, completion or proof
authority. Typed intent interpretation remains reviewed administrative coverage,
not proved natural-language semantics. This is not a general decoder-coverage or
Lean qualification result.

Admission, cold stored receipts and pending task contracts replay native captured
artifacts and the real checker. Post-check source fences reject mutations during
solver execution. Producer/configuration/solver changes, unknown answers,
unsupported source, missing solver and expired or cancelled execution fail closed.
Nested budgets cannot extend the parent deadline. The leased checker retains its
existing per-query process/output limits and sampled-memory limitations.

Container transport preserves the explicit profile and verifies the installed
Z3 binary hash before runtime startup; it never substitutes a host binary hash.
Harbor setup and execution reject mismatched intent/profile selections before
container actions. Standalone qualification accepts `--intent-requirement-contract`
and forwards the reviewed mapping into native preparation, then checks the
returned intent identity and header consumer against the archived source.
Container transport tests use authored tiny model assets and mocked Docker APIs.
The actual checkpoint/native test runs locally with an explicit isolated scheduler;
it does not qualify host-default admission or this new profile in Docker.

The prior receipt-reference fix and nomination staging remain active. The final
regression suite checks their transport and live-boundary contracts. New full-task
timing, Docker qualification, automatic post-publication successor preparation and
a matched baseline/ablation campaign remain open. The latest actual full trial
still has reward 0 and 22,587 planning-only tokens. The backlog remains 18/32
production-closed; these tests supply no benchmark efficiency claim.

Each run retains its exact command, source pins, exit receipt and JUnit/log output.
`sources/` contains the changed owners and tests; `integration-preimages.json`
records their base generations. Checkpoint/key/database/authentication bodies and
benchmark verifier inputs are excluded. No checkpoint was changed or uploaded.
