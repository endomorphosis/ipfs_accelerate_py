## What the controls observe

The three-task authored fixture has two independent roots and one task requiring
both. Context preparation and cold reopening use actual signed admission,
retained planning receipts, physical native task relations, native readiness,
AST/capsule source owners, numerical retrieval replay and live world snapshots.
The positive case reopens the file-backed owner through the actual native Quack
adapter and verifies each distinct task context. The vector fixture builds a
native lexical snapshot once before the new operation; reuse leaves its bytes
and backing artifacts unchanged. This is not a GTE training or quality result.

Negative controls include direct native-row edits, active blockers despite a
ready status, foreign task CIDs, dependent tasks, missing retained vectors,
source/query drift, freshly rehashed substituted receipts, otherwise valid
foreign semantic/retrieval source scopes, a valid broader native world, and
Source384 inline/reference/downgrade bundles. A removed native database refuses
before owner construction and is not recreated. Controlled mutation injections
around capture boundaries test cooperative currentness; they are not positive
production-path mocks.

The new source/test owners and independent read-only conclusions are pinned in
[independent review](independent-review.json). `task_ir_selection` reads the
actual persisted ModelManager catalog source with all ten exact native selectors.
It preserves nullable fields and native false-authority results. Competing
assets for one full family/dimension/geometry/schema/task/profile/format/role
namespace refuse. The actual catalog and context tests cover JSON and read-only
DuckDB stores, altered generation, distinct output heads, missing selections
and closed malformed inputs.

catalog resolver's false checkpoint/runtime authority flags. The frozen final

## Historical diagnostics and remaining work

The [development diagnostics](development-diagnostics.json) retain the initial
real positive failure: the exact expected native identity omitted the owner-added
task CID and alias. The fix added those exact keys rather than relaxing native
verification. Two later passing runs occurred while producer/tests were being
edited and are diagnostic only; their datasets and asset hashes stayed unchanged.
The final five added controls passed with frozen pins. These runs overlap the
final regression and are not added to its count.

The implemented path admits independent roots only. It does not prove query-vector
semantic alignment, authenticate Hub payloads, admit decoder runtime, execute
tasks, train models or grant completion/proof authority. Repeated source/native/
catalog observations are cooperative endpoint checks rather than atomic snapshots.
The positive fixture covers two roots; bounded API support does not establish
oversized or sixteen-root runtime capacity. Source ASTs and capsules are rebuilt;
only supplied numerical retrieval objects are reused.

The remaining plan is to recover missing format identities from original validated
checkpoint manifests, qualify each exact family/schema/task/dimension runtime
with its original embeddings, checkpoint/Hub revisions, token/span limits and
DuckDB/DuckLake inventory, then bind dependent contexts to verified predecessor
publications and their source successors. Parallel isolated worktree leases,
independent validation/review, merge currentness and durable completion/restart
must pass before lifting reviewed-profile execution guards. Autoformalized
candidates remain separate from checked proofs in the proof index. The new
8192-byte query bound is not an encoder's token budget.
