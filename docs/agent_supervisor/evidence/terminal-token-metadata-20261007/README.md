# Semantic metadata token-reduction qualification

The [improvement plan](../../terminal_token_metadata_plan.md) retains general
planning and `llm_router`. The new opt-in `common-bindings@1` coding view factors
identical inline metadata, verifies exact restoration and selects it only when
the complete coding input is strictly smaller in bytes and the named byte proxy.
The selected input and both ordinary reply-contract layers are independently
reconstructed by the audit child. Default inputs/configuration remain legacy.

The combined fresh-seal qualification passed **354 tests**, with zero failures,
errors or skips. It includes codec restoration/tampering/fallback, actual
DuckDB catalog registration, dispatcher/runner/audit-child integration and
existing transport/reply compatibility. The earlier focused qualifications
below overlap this suite; their counts must not be added as independent coverage.

The authored census selected legacy for one capsule (11,319 original bytes,
11,817 candidate), and common bindings for three (18,959 / 18,394), eight
(38,505 / 35,290), and 22 (93,321 / 82,665). These are complete authored coding
inputs with an identical authored Doctor/public instruction suffix. They use
one source file, while the recorded benchmark's four worker capsules covered
two public paths. This is representation evidence, not a measured benchmark
reduction, provider tokenizer result or total-token savings estimate.

No live provider or Terminal Bench run was launched for this qualification.
Planning remains enabled. The catalog bridge does not newly qualify active
Quack transport or a DuckLake extension deployment, and catalog nominations
cannot authorize model use or omission. Native catalog/link transactions are
separate; failed links can leave an inert row without a successful receipt.

Retained logs preserve development chronology, including the initial incorrect
single-capsule fallback fixture expectation and three dispatch failures. The
first dispatch failure exposed an audit byte-relation error, which was fixed.
The other two child-fixture failures correctly enforced exact artifact bytes
and the canonical repository. Final test bodies/hashes are bound in the combined
qualification. Temporary seal databases and authored test databases are kept
outside this published evidence directory.

The next spending decision requires an owner-emitted census of the actual
prepared coding population, followed by a separately versioned matched trial
that varies only this view. Count all retained planning/coding/lookup/repair
usage and preserve unknowns and failed attempts. Do not double-count cached
input, reasoning output or cumulative native records. Fresh formal receipt
reuse and bounded progressive disclosure are subsequent measured treatments.
