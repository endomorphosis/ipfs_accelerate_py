# Repeated compact worker edits

`mapped-span@2` permits up to 16 successful preparations within one source
session, with one outstanding proposal and fresh working-generation pins after
each confirmed edit. The previous `mapped-span@1` selection retains its original
single-edit behavior. The default remains disabled.

The owner maps and checks source; the worker writes using its existing file
permissions. Every confirmation checks the complete admitted population and
invalidates advisory candidate context. Tests rebuild native candidate capsules
and numerical formulas against the new source hashes. This does not publish an
accepted formal index or discharge a proof obligation.

## Qualification

[qualification.json](qualification.json) joins 714 distinct passing cases from
the final qualification of each test file: root integration 349, outer controls
149, client 116 and core 100. The core suite was rerun after adding the pending
confirmation matcher. Commands, JUnit results, source bindings and earlier
failures are retained separately. Historical comparisons additionally check 32
default/version-1 outer configuration outputs for unchanged bytes; these are
not included in the pytest count.

The production owner/worker Docker path completes three mapped edits with
actual owner UID 1000 and worker UID 1001. The authored provider hook changes
one admitted file through four distinct generations, preserves hidden comments
and the original inode/mode, and leaves canonical/support files unchanged.
A separate validation process checks the final authored result. There is no
original-source expansion, network access or model generation in this probe.

Its seven CLI outputs contain 6,199 bytes including seven newlines: 3,085 bytes
of source-read output and 3,114 bytes of edit results. The ten private owner
responses contain 20,229 JSON bytes plus 40 framing bytes. These counts overlap;
they must not be added. Request lengths and total bidirectional transport bytes
are not measured. These are not provider tokens or a baseline comparison.

## Failure behavior and limits

A matching confirmation failure blocks further version-2 mappings in that
session, including failures in the owner's surrounding context checks, final
peer check or response send. Stale or foreign confirmations cannot consume the
active proposal. Source inspection remains available. Successful kernel send
does not acknowledge receipt by the client; an uncertain client result always
requires stopping mapped edits and inspecting the source without automatic
retry.

The existing 64-connection, 524,288-response-byte and selected session-lifetime
bounds still apply. The 16-preparation limit does not promise enough capacity
for 16 edits plus arbitrary reads. Each edit must lie within one supported
retained codec interval. File creation, movement and deletion remain outside
this mapping contract. No atomic filesystem transaction or writer exclusion
is claimed.
