# Prepared features after native target replay

This is an unimplemented optimization proposal for a new additive scan profile. It has no timing, memory, CUDA or larger-head qualification credit. The qualified shared transport and its receiver checks should keep their existing meaning.

The current [shared worker](../../../ipfs_datasets/ipfs_datasets_py/optimizers/logic_theorem_optimizer/codebase_inventory_shared_worker.py) completes native replay, decodes the returned target for its source binding, and calls the existing matrix helper. The feature helper's `_target` path then decodes and serializes the full target four times, including its manifest and receipt, before extracting projection expressions. The coordinator also calls that feature path to compute coverage during current target reconstruction. Static enumeration of the present five-page workflow gives 1,645 eligible coordinator coverage calls per mode, compared with 294 numerical rows. These are static workflow counts, not measured call or timing observations.

The first candidate is a private factory that accepts the operation-owned result of complete native target replay, decodes that target once, checks its full ASCII size, and prepares immutable projection counters, descriptors, source binding and coverage. A new matrix helper can consume those fields while retaining only feature data and identities. This would remove repeated feature extraction decodes and three of its four serializations. A later candidate could reuse the replay's already decoded value after full canonical equality succeeds; qualify that private API separately.

The factory must preserve the entire [native validation](../../../ipfs_datasets/ipfs_datasets_py/logic/software_contracts/codebase_resume_shared_targets.py): restore, source bytes and provenance, AST reconstruction, authored contracts, native lowering and byte-exact equality of the complete rebuilt target. Minting a prepared row follows those checks. A public envelope, persisted cache entry, `ready` flag, hash or caller assertion cannot substitute for them.

The [feature validator](../../../ipfs_datasets/ipfs_datasets_py/optimizers/logic_theorem_optimizer/autoencoder_projection_features.py) independently limits the complete ASCII target to 4 MiB. Native UTF-8 and compact ASCII limits do not imply that limit, especially for escaped Unicode and metadata. Preserve it, all projection and descriptor validation, and the required feature basis. Bind each prepared row to the exact target digest, source digest, shared inventory, current head and member identity. Freeze the vocabulary descriptors or independently check their mutation before use.

Keep the existing arithmetic and traversal from the [matrix helper](../../../ipfs_datasets/ipfs_datasets_py/optimizers/logic_theorem_optimizer/codebase_inventory_feature_worker.py): sorted dictionary keys, positional list paths, depth limits, ASCII atom encoding, ordered `math.log1p`, Python `sum`, `math.sqrt` and division. A change to vectorized reductions needs its own numerical qualification. Release the full target and parsed manifest before processing the next row.

Coordinator coverage preparation must come from the freshly reconstructed native target and verified saved target/source joins inside the owning current observation. A worker claim or cached coverage record cannot authorize current receiving. Preserve source, model, catalog, SQL and final held-FD CAS closing checks.

Acceptance requires exact feature vectors, descriptors and coverage against the existing shared profile; genuine Unicode size-boundary and malformed-projection refusals; forged or mutated prepared-row and vocabulary refusals; late-row failure before Torch; and successful one-target retention controls. Measure actual decode and serialization calls, bytes, scan phase times and parent/child RSS in a fresh equal-work campaign. First qualification would cover the selected structural 8D CPU workload. Trained semantic 8D, 384D, 768D, 4096D Leanstral and CUDA remain separate gates.
