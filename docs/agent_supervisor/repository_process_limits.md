# Optional kernel limits for repository processes

`PipelinePhase.run` accepts `hard_limits=RepositoryProcessLimits(cpu_seconds=2, address_space_bytes=64 * 1024 * 1024)`. The phase and its existing supervisor/datasets reservations must already be admitted. The default `None` preserves existing behavior.

The profile binds exact positive integer limits to the phase RAM declaration, thread count and remaining invocation time. It uses the existing datasets `codebase_process` launcher and trusted system `prlimit`; it neither reserves resources again nor invokes a container engine. Linux is required, and a missing native helper fails before workload launch without falling back to sampled execution.

The kernel enforces equal soft/hard limits for CPU time and virtual address space per process. The existing runner also sets core size to zero and limits each output file to the phase disk declaration. CPU limits include process threads; forked children inherit the limit but have independent CPU counters. Virtual address space is different from resident memory. Aggregate process-tree RSS, process count and named-root disk usage remain sampled. Threads obey the existing cooperative environment settings. These controls do not provide a cgroup, GPU budget, filesystem quota or isolation against privileged code.

After a hard-mode invocation, `phase.last_process_enforcement` describes the requested native limits and actual process outcome, including start, return code, timeout and cleanup. A missing helper records no process start. The receipt is diagnostic and grants no proof, execution or completion authority. Read it before the phase is finalized and persist it through the caller's normal evidence owner when needed. The pipeline's overall `hard_enforcement` remains false because its complete aggregate resource envelope is still sampled.

The final qualification contains 52 distinct checks: 20 new profile/process checks and 32 unchanged pipeline regressions. Within the new suite, five workload paths execute under actual default host admission: limit inheritance plus default opt-out, CPU exhaustion, address-space exhaustion, per-file exhaustion, and timeout with a forked descendant. A sixth real-owner case explicitly injects only an unavailable prlimit helper. Fourteen other cases validate dimensions, phase bounds and unsupported-platform refusal. Legacy tests retain their own pure, injected-host and actual-host fixture scopes; their total must not be represented as 52 actual-host workloads.
