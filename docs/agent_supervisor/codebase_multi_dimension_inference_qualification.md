# Native 768D inference and Leanstral 4096D admission

The [four-width plan](codebase_multi_dimension_inference_plan.md) covers 8D, 384D, 768D and 4096D across all four IR families. This increment implements a resident native 768D encoder, private 768D head, batched head and a Leanstral 4096D capability adapter. The encoder's first CUDA measurement improved warm throughput; the final head CUDA benchmark remains pending after an allocation failure. A trained 4096D head still requires verified native embedding outputs. The earlier [successor qualification](codebase_successor_expansion_qualification.md) remains unchanged. All 32 production acceptance rows remain open.

## Implemented paths

- [SourceEmbeddingDeviceSession768](../../../ipfs_datasets/ipfs_datasets_py/logic/formalization/autoencoder/source_embeddings_device_768.py) admits every stored tensor in the pinned multilingual GTE model once, retains its tokenizer and tensors, and checks ordinary-file custody and model values around calls. It produces genuine 768 values with CLS/L2, rejects truncation and records actual tokens/device/dtype/profile. CUDA is the default when available; `optimized=False` selects CPU.
- [DeviceDimensionalSpanSession](../../../ipfs_datasets/ipfs_datasets_py/optimizers/logic_theorem_optimizer/legal_span_device_inference.py) owns an authenticated native 768D source-span checkpoint and its live resource lease. The GPU GRU uses scoped strict float32 CuDNN settings, synchronizes before restoration and checks the ambient policy. CPU opt-out avoids CUDA precision queries. Stored checkpoint/Adam and historical producers are preserved.
- [DeviceBatchedDimensionalSpanSession](../../../ipfs_datasets/ipfs_datasets_py/optimizers/logic_theorem_optimizer/legal_span_device_batch_inference.py) batches complete valid sources, materializes the four output tensors on CPU once and uses the inherited per-source canonical decoder. Actual token padding and model/checkpoint size determine a conservative memory estimate; over-budget requests refuse before allocation. CPU opt-out retains the singleton reference path.
- [Leanstral 4096D adapter](../../../ipfs_datasets/ipfs_datasets_py/logic/formalization/autoencoder/source_embeddings_4096.py) implements bounded read-only discovery, typed owner requirements and diagnostic token/vector validation. Production `embed_rows()` refuses until trusted native owner integration is available.

Use the heads inside an owned inference worker process, with an exact shared scheduler and admitted parent lease. Torch's CuDNN flags are process-wide during the strict GRU scope; unrelated concurrent CuDNN operations in that same process are outside this ownership contract. Numeric CUDA parity is an explicit measured tolerance, not a bitwise identity or proof claim.

## Leanstral 4096D scope

The [read-only preflight](../../../../artifacts/codebase_ir_terminal_bench/leanstral-source4096-preflight-20261003-02/receipt.json) and [16 controlled protocol checks](../../../../artifacts/codebase_ir_terminal_bench/leanstral-source4096-preflight-20261003-02/tests-receipt.json) passed their declared discovery/diagnostic scope. Native GET metadata reports input hidden width 4096, backend build `b1-571d0d5`, server slots 4 and context 32768. Client concurrency 1 is a separate bound. Embedding mode, native output width, pooling, device and physical microbatch remain unattested, so actual 4096D embedding/head qualification is false.

The small model manifest declares the cached 67,135,119,264-byte GGUF identity; this work did not read/hash those full weights. GET observations do not establish current process identity or actual numeric inference. This task made no service restart, launch/configuration change, generation request or embedding request. Future owner integration must supply genuine complete 4096D outputs before fitting a distinct head and optimizer lineage. The current native source-span head supports 768D; this increment does not implement or select a 4096D numerical head.

Remaining gates include family-specific 768D/4096D CodebaseIR training and source-correspondence qualification, full successor scans and signed worker dispatch for each new producer/task, native Leanstral embedding admission, tensor checkpoint storage equivalence and same-lineage federated updates. Learned output remains candidate logic until an independent checker establishes the relevant proof obligations.

The [machine review](../architecture/repository_proof_index_and_codebase_ir.multi_dimension_review.json) pins the implementation, controls, attempt history, 16-cell plan and unchanged earlier acceptance table. Its retained directory manifests use CIDv1 with DAG-JSON/SHA-256; no IPFS publication was performed.
