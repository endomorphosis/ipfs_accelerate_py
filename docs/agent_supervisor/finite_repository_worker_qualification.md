# Finite repository worker and successor qualification

On 2026-10-02, the authored seven-file repository completed a real native worker
loop in **83.397 seconds**: capture, finite observations, signed admission,
complete task materialization, native prerequisite completion, isolated residual
edit, public validation, Git publication, STOP, successor admission and an
independent cold comparison. The offline container wrapper took 118.465 seconds,
including source copying, resource admission, deployment and removal.

This extends the [previous admission qualification](finite_repository_admission_qualification.md).
It qualifies one **two-task, five-input, model-off** fixture. It runs no training
or model inference and makes no unrestricted Python correctness claim. All 32
[production acceptance tasks](../architecture/repository_proof_index_and_codebase_ir.todo.md)
remain open.

The retained [native result](../../../../artifacts/codebase_ir_terminal_bench/finite-worker-qualification-20261002-13/native/result.json)
and [container execution record](../../../../artifacts/codebase_ir_terminal_bench/finite-worker-qualification-20261002-13/container-execution-final.json)
record the completed run. Earlier attempts remain separate.

## Implemented crossing

[Finite execution reservation](../../ipfs_accelerate_py/agent_supervisor/runtime/finite_repository_execution.py)
holds an actual native orchestration lease and returns a private live scope. The
signed serialized envelope describes that scope; loading its JSON cannot grant
launch permission. The scope binds the complete original task population,
actual prerequisite check/completion receipts, the exact ready residual revision,
current source/head/evidence/policy, native owner identity and an immutable
candidate descriptor. Existing typed ownership supplies the later actual claim,
attempt, lease and fencing token.

[The finite candidate runner](../../ipfs_accelerate_py/agent_supervisor/runtime/finite_repository_candidate_runner.py)
authors a readonly external handoff and materializes its exact `calc.py` edit
inside an allocated worktree. It verifies the complete public signed context
without reading the profile's private key. It requires the original preimage,
same Git repository and baseline, exact native objective and closed integer
lowering. Its receipt grants no proof, completion or publication authority.

[The admitted runtime](../../ipfs_accelerate_py/agent_supervisor/entrypoints/admitted_benchmark_runtime.py)
accepts this scope for the exact installed worker command. It retains both CLI
tasks and dispatches the one native-ready residual. Existing single-task
automatic refresh and retrieval gates keep their existing scope. The new route
uses a separately captured and signed successor after STOP.

Fresh typed checks and executable callbacks occur before the native owner's
lock. The final locked fence reads bounded physical SQL rows and detached
source/artifact/launcher descriptors before process birth and child registration.
Task, source, policy, candidate or prerequisite drift prevents launch. SQL
projection now reads DuckDB row values by position, including completion receipt
values; iterating these mapping rows would otherwise read column names.

The scope renews its real lease, including when preview auto-renewal is disabled.
It releases only after successful native STOP, an absent marked process tree and
successful isolated worker cleanup. Source drift and cancellation cannot prevent
STOP. A failed cleanup retains the lease and renewal in an in-process registry;
durable owner-crash recovery and a public release-retry API remain unqualified.

## Resource and deployment scope

The worker envelope holds 4 CPU slots, 4096 MB and eight estimated child slots
through STOP and UID cleanup. The wrapper separately holds a host reservation
for a nonprivileged container with 12 CPUs, 8 GiB and 512 kernel tasks. Network
access is disabled during execution. Owner UID 1000 and worker UID 1001 use the
existing installed worker boundary; private owner paths remain inaccessible to
the worker. Runtime model/provider call counts and training steps are zero.

The native lease is admission accounting. Docker supplies the stated aggregate
container limits; this run does not prove independent per-worker CPU/memory
enforcement. The host wrapper uses an explicit fixture ledger, not a shared
cross-daemon fleet owner. The container is removed before its host reservation is
released. Final native shared-scheduler and fixture-host lease/waiter counts are zero.

The wrapper copies selected Python and small package resources, including SQL
migrations, before launching from readonly copies. Its retained manifest records
per-file identities; the native run pins ten selected producers. The execution
record reports that the originals matched those copies at the end of the run.
At the later review, the original copied-source directories are absent. All ten
selected producer identities match current originals and separately retained
copies from the later offline tests; these are explicitly later observations.
The native artifacts and 77 historical parent-artifact pins remain intact.
These sequential observations are not an atomic Git checkout or a complete
executed-dependency attestation. The immutable image identity, actual container
identity and namespace observations are in the execution record.
