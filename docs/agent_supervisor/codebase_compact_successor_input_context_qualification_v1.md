## What the candidate checks

The [sealed candidate README](../../../../artifacts/codebase_ir_terminal_bench/compact-successor-context-candidate-20261007-01/README.md) describes a reference-only input context for a future manifest version 8. Its candidate schema is distinct from an authenticated V8 context or pending contract. It preserves the complete immutable V6 parent admission and V4 planning receipt, the legacy root and DAG-JSON completion@1, and the separate current selection, source delta, root and RAW completion@3/pages@3/chunks@2.

The [context implementation](../../../../artifacts/codebase_ir_terminal_bench/compact-successor-context-candidate-20261007-01/context.py) requires the parent's declared current head, membership and complete model to equal the current selection/root, with matching previous-head/model and source-delta bindings. Legacy and current transport root/completion identities may differ. This changes transport for the same declared source/model lineage; it does not authorize a transition to another source generation.

Complete supplied materials are detached and precharged before artifact decoding: at most 32 unique members and 32 MiB. Context wire is limited to 64 KiB and each reference to 2 KiB. Additional private metadata roles retain 4 MiB legacy-completion, 256 KiB selection and 8 MiB delta limits. These roles do not extend the already sealed owner-store implementation or its configuration. Plain-tree and string budgets are checked before encoding.

Recorded source joins cover the complete declared path population. Available RAW source CIDs must match declared SHA256. Opaque members without a source CID remain explicitly unknown; matching a digest neither establishes a fresh source read nor verifies executable mode. Independently valid implementation maps are preserved separately for the root, selection and source delta.

The detached requirement projection preserves the complete graph, ordered task population, task specifications, dependencies, scope, outputs, validation and acceptance checks, pending requirements and their identity, policy, roots, owner and plan bindings. A provisional guard requires a nonempty list of required post-execution test/review requirements at candidate assurance. This is a declared restriction, not full native planning recomputation. All signature, child authentication, pending replay, native receiving/currentness, store custody, execution, proof, production and V8-readiness flags remain False.
