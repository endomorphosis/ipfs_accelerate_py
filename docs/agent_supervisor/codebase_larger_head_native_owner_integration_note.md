The proposed next milestones are:

1. Extend the qualified adapter boundary into a separately reviewed production source interface, retaining failure, cancellation and release evidence. Production `source_embeddings_4096.embed_rows` and the existing positive-step span trainer remain closed until their separately reviewed interfaces are implemented.
2. Add a versioned CodebaseIR source task whose contract distinguishes encoder input width, learned latent width and formal target codec. Bind exact source spans, tokenizer policy, producer identities, train/tune/canary roles, binary tensor state and complete optimizer state. Explicitly declare fresh optimizer initialization when importing a weight-only sidecar.
3. Add new scan/model schemas for that task. Preserve every inventory member and deferred/opaque disposition, compare all cold/resumed/default/reference pages, and keep independent source/model/checker observations through signed successor admission and worker START. Retain the existing structural profiles without widening their schemas.
4. Qualify each encoder/head family separately before joining proof-index evidence or same-lineage federation. Formal checker results own proof authority. Federation requires matching width, task, encoder, parent, parameter layout and optimizer policy; the existing future IPFS Accelerate and MCP++ synchronization hooks remain separate from completed model aggregation.

The full owner currently hashes the entire model on every operation. The reported three-row pilot spent 82.221 of 97.527 seconds on that integrity step. Larger bounded operations can amortize that cost while preserving the declared native profile. A faster persistent or incremental verification policy would require a separately authenticated content boundary and mutation controls; filename or file-stat equality alone would not preserve the current full-content contract.
