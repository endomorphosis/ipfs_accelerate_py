# Capsule column context replacement

The new treatment changes the readable representation of selected capsule and
admission rows. It preserves every original value and restores the full native
transport and coding prompt exactly. It is separate from the existing one- and
two-capsule budget comparison; defaults and source-selection policies remain
unchanged.

Select it explicitly with `--semantic-metadata-view capsule-columns@1` on the
indexed semantic coding route using `supervisor-semantic-router-input@1`.
The worker, Terminal supervisor, benchmark comparison and retained input audit
recognize the same profile. It cannot be combined with alternate source-input or
query-reference projections. Planning, provider-free Doctor, census and transport
`@2` routes reject it. No default is changed.

The model sees readable `shared`, `columns`, `rows` and `extras` tables for
capsules, admissions and admission references. Uniform literal values appear
once; nonuniform values remain in their rows. The inverse preserves order,
multiplicity, unknown fields and the difference between missing, null and empty
values. Independent native and candidate pins and aggregate byte/node/depth
bounds constrain restoration. Selection compares the complete rendered input,
including explanatory overhead. It requires smaller bytes and a smaller supplied
token count, or the declared byte proxy when no counter is supplied. An invalid
or failed supplied counter retains the original. Later whole-prompt selection
can also cancel the treatment and records that decision.

The offline experiment generates bounded, authored four- and eight-function
sources. Actual indexed semantic preparation, ContextCompiler, source-freshness
checks, capsule codecs and the router's complete input selection run for each
legacy/one/two budget pair. Only provider discovery, allocation and generation
use an explicit scripted Codex seam. Canonical sources are committed only in the
private fixture, and coding uses a separate real allocated Git worktree sharing
its common directory. No container identity or source guard is fabricated.
No live provider, CLI, model or training runs.
Required instruction/source bodies, literal constraints, security obligations
and unknown facts remain identical within every pair. A larger representation
or a failed counter retains the native input; savings are never forced.

The tokenizer uses the existing hash-verified local `o200k_base` ranks directly,
with no downloader. Its counts are proxy estimates, with no established Grok
or remote Codex compatibility, message-framing coverage, provider usage or billing authority.
Both complete rendered coding prompts and the complete authored workload are
measured. The same host-only discovery inventory, expansion request, actual
verified capsule-expansion response and guidance are charged once to both arms.
This workload tests source-current host expansion. It does not deploy an
initial-root worker resolver, observe agent navigation or establish ingestion.
No capsule or source body is omitted by this treatment.

Run the module from the fresh checkout using the root-owned leased qualification
helper and an existing owned scratch parent:

```text
python -m benchmarks.agent_supervisor.container_coding.terminal_capsule_columns_experiment \
  --scratch-root /absolute/owned/scratch --output /absolute/new/result.json
```

The bounded result contains hashes, measurements, selected modes, preservation
checks and listed source-code pins. Authored source and prompt text remain in
private transient fixtures. The fixture identity and cleanup census are checked;
unavailable cleanup prevents qualification and preserves evidence. Output files
are new private regular files, never overwrites. `validate_report` requires an
independent FULL canonical report pin and checks population, scope and arithmetic;
it does not rerun the experiment or authenticate a self-sealed replacement.
Authored fixture storage is bounded at 128 MiB for the six real local
DuckDB/DuckLake contexts. This does not change prompt, report or scheduler limits.
Cleanup refusals retain closed reason codes and counted prefix bytes/files;
the prefix is never claimed to be a complete refused population.

Results qualify this finite offline representation exercise. They establish no
live TerminalBench reward, whole-session token reduction, source semantics,
proof, completion or default model promotion.

## Retained measurement

The `measured-v02` run on 2026-10-14 completed all six pairs, source-pin checks,
exact restoration checks and private fixture cleanup. These counts use the local
tokenizer proxy described above. "Authored workload" includes the identical
four-message host expansion workload once in each arm; it is not a measured
agent session.

The five-capsule pairs reduce this initial prompt proxy by about 11.2% and the
authored workload proxy by 6.6–6.7%. Two-capsule pairs reduce them by about 1.7%
and 1.2%. One-capsule candidates are larger, so both keep the original input.
These are within-budget representation comparisons; they do not measure the
benefit of reducing capsule budgets.

The fixture used 90,675,167 bytes. Its declared storage allowance is 128 MiB;
the report remains bounded at 1 MiB and individual measured messages at 256,000
bytes. An earlier 64 MiB cleanup refusal remains as failed evidence. Only this
scratch storage allowance changed; native resource scheduling did not change.

The retained report is `measured-v02.json` in the local qualification artifact
directory `artifacts/capsule-columns-context-replacement-20261014-01`. Its full
canonical SHA-256, including its internal seal, is
`1a359a9f3dfd5ce9115fc821f40ac11607698486004211ba3ff7aa4e036d8aec`.
The qualification record retains prior failed attempts and latest passing results
for 740 distinct tests across codec, dispatch, inverse reconstruction, metadata
selection, source policies, comparison reporting and the offline experiment.

A live efficiency claim still requires paired successful Terminal Bench runs,
native session usage accounting and observed retrieval costs. Moving capsule
bodies out of the initial input also requires a deployed worker resolver for the
same initial semantic root; the current host-only expansion exercise supplies no
such qualification.
