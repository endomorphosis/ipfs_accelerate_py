# Durable scoped header proof inventories

The inventory retains an independently admitted key-to-receipt population in
the original sealed Doctor SQLite owner. It connects [cache admissions](header_proof_cache_bridge.md)
to explicit restart and the [typed Terminal host](terminal_header_proof_admissions.md).
Its seal preserves custody; it grants no proof, completion or execution authority.

## Persist the admitted population

`persist_header_proof_inventory` requires the exact scoped analysis, existing
Hammer/Gate, admitted handle tuple, independently expected key IDs and
`(key_id, generic_receipt_id)` pairs, and independent digests of both canonical
native-owner and generic-cache paths. Missing, duplicate or foreign entries refuse.

The closed `HeaderProofCacheInventory` retains task/repository/source-scope
identities, both owner-path digests, sorted key/receipt entries, original typed
key-custody references and bridge/codec/inventory implementation digests. It
references the original complete preparation rather than copying source bodies.
It supports at most 32 entries and 256 KiB of canonical inventory bytes.

Persistence checks the complete current admission population, appends one record
to the same sealed owner and reloads it. It performs no kernel replay or generic
positive-cache write. Existing native denial bookkeeping may write control state.
Retain the typed reference and independently expected inventory CID outside the
loader. No latest-row selection, cache enumeration or locator discovery occurs.

## Load with independent current inputs

`load_header_proof_inventory` requires the typed reference, independently expected
inventory CID, task/scope identities, both path digests, existing current Hammer/
Gate and independently rebuilt preparations for the entire population. Explicit
profiles, actual trusted executable pins and requested bounds remain required.
Preparations join the same exact scoped analysis object.

Complete preflight checks every entry before the first kernel call: closed
schemas, original sealed inventory/custody/proof lineage, exact preparation/full
key, signed source, profiles, implementation versions, executable pins and bounds.
Loading a sealed proof never constructs generic accepted evidence. Changed emitter,
codec or inventory provenance refuses before import. A later source, custody or
population mismatch detected by preflight prevents the first replay.

After preflight, each bridge import performs fresh native kernel replay and checks
the independently expected generic receipt ID before `Gate.put`. A mismatched
receipt returns no handle and avoids that positive-cache write. Earlier native
bookkeeping and executable effects remain possible. The complete tuple returns
only after every entry succeeds and final bindings remain current.

Original objects, paths/device/inode, seal-key continuity, inventory reference
and the complete current population stay checked around operations. Checks are
sequential, without an atomic lease or rollback. Earlier valid imports may remain
after a later replay or expected-receipt check fails. A syntactically valid but
incorrect expected receipt ID is rejected after that entry's fresh replay and
before its cache write; earlier valid entries may already have been imported.
Explicit empty inventories perform no kernel call;
they do not infer a missing proof population.

Host reconnection is explicit. Reopen the original SQLite file/private seal key
and DuckDB cache, rebuild current signed analysis/preparations, then load. Store
identity includes a basename rather than the full path; store/authority IDs and
hashes alone do not authenticate physical ownership. Independent path admission
and current fences remain required. Seal keys stay private.

## Terminal and version migration

Supply returned handles and the independently retained population through
`TerminalFormalStatusOwner`. Use the same scoped analysis object as the restarted
preparations. Equivalent-looking replacement objects do not satisfy that join.
The inventory cannot replace current bound render/commit checks or turn
historical acceptance into completion authority.

Emitter/codec upgrades can change receipt IDs under unchanged native keys.
Preserve old inventory/cache refusals and admit a versioned key/profile with
corresponding native preparation/custody when required. Inventory-loader upgrades
also require an explicitly admitted provenance/version migration. Do not clear
quarantine, overwrite expected IDs or replace owners to conceal identity changes.

Requested limits do not certify OS enforcement. Record byte bounds do not bound
lineage-prefix work, hashing, SQL or arbitrary executable effects. Measure those
costs separately before model access or token-benefit prediction. This API creates
no owner, automatically selected producer, worker input change or required-fact
omission. Actual live accepted coverage and token savings remain unmeasured.
