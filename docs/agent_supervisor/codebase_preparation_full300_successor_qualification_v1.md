## Performance baseline and next work

Actual process durations were **25.565 seconds producer, 163.302 seconds receiver, 30.531 seconds normal reference and 647.115 seconds controls**; the complete campaign took **869.737 seconds**. These processes perform different staging, restart and validation work. The receiver's additional protocol work is substantial, and this campaign does not establish an overall wall-clock speedup or general throughput claim. The measured benefits are the avoided parser and duplicate frontend calls with full output parity.

The next candidate is bounded reuse within a single preparation operation. Prefix validation verifies each saved AST wrapper, then runtime restoration reads and decodes it again and re-encodes previous projections to recover byte totals. Nineteen pages traverse **2,736 prior AST records** before explicit load, validation and completion calls: 448 in the producer and 2,288 in the initial receiver. The full successor has another such page traversal. Carrying verified bytes, detached canonical projections and cumulative sizes through these steps could remove repeated work. This remains a source-derived opportunity until separately implemented, measured and qualified.

Each reuse must retain source, context, page-anchor, checkpoint and held-file custody checks, including inode, size, mtime and ctime observations. Within-operation CAS corruption/replacement and callback-alias controls are needed. Start with operation-local reuse, enabled by default with an explicit opt-out; cross-operation admitted-prefix caching needs separate qualification. The store's 64-blob unchanged-revision hint does not execute in this changed-snapshot publication profile and is not attributed as this baseline's bottleneck.

Global semantic assembly still runs as one complete bounded operation, and root capture remains whole-inventory. Resumable semantic fact/index pages, automatic signed supervisor worker transport and database reopen remain separate milestones.
