# Native owner prelaunch assignment qualification

This stage qualifies an owner-side library gate before source-proxy publication.
It consumes the original live `NativeSourceTaskAdmission` and
`NativeSourceWorktreeAllocation` objects. It checks the exact native task and
claim, canonical repository, allocated workspace, Portal projection and current
worktree lifecycle. Detached observations or retained historical JSON do not
become assignment capabilities.

The finite experiment reuses the retained `_allocation_case` authored fixture.
DuckDB, typed owner commands, the process-serialized coordinator, native claim,
Unix grant, sealed Portal projection, Git worktree and lifecycle records are
real. `FakeQuackTransport` and deployment metadata are explicitly authored
seams. No Docker boundary or separate worker UID is qualified, and no provider,
CLI, model, learned checkpoint, target program or training is run.

The scenario binds the existing selected source service, explicitly provisions
the two selected authored fixture files, captures the gate,
starts the opt-in gated source broker and reads its existing inert payload.
It compares literal source bytes between the canonical and allocated trees,
observes the initial gate and performs a genuine native
lifecycle renewal. It then checks refusal after native task revision and full
body faults, an expired allocation-record fault, a writable allocation-mode
transition, an authored owner-UID mismatch and genuine native claim release.
The UID fault does not change the kernel UID. The stale record and task faults
are restored before subsequent checks; the native claim release is final.
Native and Portal task identities remain separate.
Trusted fixture setup uses `provision_authored_prelaunch_sources(case)` before
capture. It checks owner-held regular single-link files through stable no-follow
descriptors and removes only group/other-write bits from the selected canonical
and allocated files. The report counts both files and independently checks that
bytes and executable bits remain unchanged. Runtime guards and earlier default
fixtures are unchanged; production code never chmods source to admit it.
The optional gate requires owner-controlled canonical and allocated roots and
ancestors, and selected files without group/other-write permissions.
Every stale check must refuse both the gate and another broker source read,
with no increase in returned native payload bytes.

The host first binds the shared current-source lookup through its original
allocation handle. It then supplies those same live objects at the library
boundary:

```python
assignment = capture_repository_world_prelaunch_assignment(
    task_admission=live_task_admission,
    worktree_admission=live_worktree_allocation,
    prompt=literal_prompt,
)
broker = start_source_lookup_worker_broker(
    **original_broker_arguments,
    world_prelaunch_assignment=assignment,
)
```

`original_broker_arguments` retain the exact server, task admission, worktree
admission, canonical repository, allocated workspace and literal prompt. The
optional gate is checked before proxy grant publication and again before source
reads. Its declared prompt binding is literal-only; it does not authenticate
compiler output. Serialized observations cannot substitute for either handle.

The supported consumer is the owner-held source-proxy library. This does not
claim that a shipped Terminal call site invokes it, that context is compiled,
or that a world packet is ready to dispatch. All execution, proof, completion,
compiled-packet and `world_dispatch_ready` flags remain false.

Root runs the bounded experiment under the independently pinned native resource
owner, using a fresh qualification label and sealed dependency environment:

```text
python -m benchmarks.agent_supervisor.container_coding.terminal_world_prelaunch_experiment \
  --scratch-root /absolute/owned/scratch \
  --output /absolute/new/private-report.json
```

The content-free report contains declared source-file hashes, assignment hashes,
finite checks and counts. It never exports native credentials, source bodies,
SQL rows or absolute private paths. `validate_report` requires an independently
held FULL canonical report SHA-256, including the internal seal. Validation
checks custody and the finite observation contract; it does not rerun native
operations or authenticate a report using its self-seal alone.

Scratch cleanup reuses the frozen bounded held-root-contents owner from the
prior world-packet experiment. All native contexts must close first. A complete
owned, nonsymlink census precedes any permission adjustment or deletion. Only
censused directory inodes may gain owner-write; file inodes are not chmodded.
Cleanup uses held directory descriptors and never removes the root name. An
empty private root shell remains. Replaced namespaces or foreign entries are
preserved and leave qualification incomplete. Scenario failures retain private
scratch rather than claiming successful cleanup.

The locked datasets and kit source revisions remain independently pinned.
Each actual qualification must verify the existing shared resource policy
before admission and its own release afterward. This stage does not create a
second global resource ledger or reconfigure the existing owner.

The 2026-10-14 qualification passed 192 distinct current cases: 69 existing
source/allocation regressions, 74 prelaunch assignment cases, eight broker
integration cases and 41 finite-report cases. The independent standalone run
passed all 18 checks, retained two positive assignment observations, performed
one read-only native source read, observed genuine lifecycle renewal and refused
six stale states at both the gate and source-reader boundary.

Native cache-callback and namespace regressions cover lease release after cache
reads, source changes after native clock callbacks, and root/ancestor replacement
with identical bytes. The gate closes native fences after cache replay and
checks named filesystem custody after reads. Its process-local issuance and
closed instance shape reject observation replay, detached copies and method
replacement.

The first 32-case qualification attempt recorded six passes and 26 refusals
because inherited authored source files were mode 0664 under umask 0002. A
private stat diagnostic confirmed the mismatch. Trusted setup in only the new
fixtures provisions exact selected files before capture, preserving bytes and
executable bits; the nested fixture also provisions its exact authored parent
directories. Production guards and shared legacy fixtures are unchanged. The
initial failures and diagnostic remain retained for review.

Private evidence lives in the parent workspace under
`artifacts/world-packet-container-20261014-01`. `qualification.json` records the
implementation commit, source/dependency pins, latest test populations, resource
leases, static review findings and earlier failures. `measured-v01.json` records
the final standalone result; `measured-report-identity.json` retains its separate
full canonical hash, and `report-validation.json` validates that externally
held pin and the declared source-file population. Every admitted run released
its lease and preserved its pinned shared policy.

The next integration boundary is an authenticated owner observation handoff
that preserves the claimed attempt and source custody through actual worker
birth and the authorized permission transition. Container dispatch, compiled
world-packet issuance and whole-session token savings remain unqualified here.
