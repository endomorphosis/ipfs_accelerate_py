The 768D encoder and batched head now pass actual CUDA replay and retained-byte validation. ## Actual 768D replay

The [latest native run](../../../../artifacts/codebase_ir_terminal_bench/native-768-device-qualification-20261004-04/result.json) completed in 67.71 seconds, replaying the same diagnostic checkpoint and training index. It performed zero new fits and zero inference fits; the two original bounded setup fits remain explicitly inherited. Checkpoint and Adam bytes were unchanged. CPU, singleton CUDA and batched CUDA canonical decisions matched for 1, 16 and 32 rows. All four CUDA head-logit comparisons had maximum error at most 1.20e-7 against the unchanged CPU numerical model, within the declared 5e-5 bound.

Each warm timing is the median of three observations on the same 32 short authored sources:

| Rows | Encoder CPU / CUDA | Head CPU / batched CUDA | Singleton CUDA / batched CUDA |
| --- | --- | --- | --- |
| 1 | 3.24x | 0.62x | 0.86x |
| 16 | 7.97x | 1.44x | 2.03x |
| 32 | 11.94x | 1.52x | 2.21x |

Ratios below one mean the GPU path was slower. Small-row latency is therefore still a tradeoff; no automatic device switch changes the admitted input profile. CUDA remains the default in the new sessions, with explicit CPU opt-out. These measurements qualify the bounded diagnostic head, not production model quality, long contexts or general CodebaseIR correspondence.

Peak Torch allocation was 2,738,801,664 bytes. Owned sessions closed, the process-local cuBLAS workspace was cleared, allocation returned to zero and the root lease was released. The [closed audit](../../../../artifacts/codebase_ir_terminal_bench/native-768-device-closed-audit-20261004-01/receipt.json) independently verifies retained sources, numeric/canonical joins, checkpoint/Adam identity and reported cleanup fields. Its scope is ordinary bytes and report consistency, without execution-origin or kernel-resource attestation.

## Implemented 4096D head

- [legal_span_4096.py](../../../ipfs_datasets/ipfs_datasets_py/optimizers/logic_theorem_optimizer/legal_span_4096.py) adds a separate versioned checkpoint lineage with an actual 4096-wide adapter. It can copy source tensors from a pinned source-only parent while initializing its own adapter and Adam lineage. Private inference restoration validates exact float32 weights, retained Adam moments and step scalars, progress, stored manifest hashes and provenance without constructing an optimizer. Training validates supplied manifests against their admitted hashes. A control proves input index 4095 reaches the adapter. Positive-step training remains refused until trusted Leanstral ownership is implemented.
- [DeviceLeanstral4096SpanSession](../../../ipfs_datasets/ipfs_datasets_py/optimizers/logic_theorem_optimizer/legal_span_4096_device_inference.py) adds default batching/CUDA selection, CPU opt-out, strict scoped CuDNN precision, complete-source memory limits, checkpoint/tensor custody, cancellation and lease cleanup. It chooses an uninitialized CUDA device without opening a CUDA context before child admission. Its numerical profile is now `native-4096-source-span-batched-device-float32-cpu-decisions/v2`. Currently, inference requires explicit opt-in to an untrained synthetic fixture. Caller vectors, JSON receipts or booleans cannot establish native Leanstral admission.
- [owned_tensor_value_guard.py](../../../ipfs_datasets/ipfs_datasets_py/optimizers/logic_theorem_optimizer/owned_tensor_value_guard.py) compares every value, sign bit and finiteness condition on CUDA, then extracts one final host decision. CPU and opt-out preserve reference comparisons. Metadata and comparison-memory bounds precede allocation. PID/thread, pointers, source/profile and reference custody remain the session's responsibility. This helper is integrated only into the new 4096D path; historical 768D producers remain unchanged.

The session anchors its private reference to immutable, complete float32 bytes from the independently restored CPU checkpoint before upload. At entry and exit it checks anchor identity and every reference byte, including signed zero, before comparing model values with the reference. This closes the paired model/reference mutation gap. The extra check requires one bounded reference transfer to CPU per CUDA boundary; the helper's single host decision does not describe the whole session's synchronization cost. Metadata and conservative host/device memory reservations precede concatenation and copies. These checks assume an owned worker process; they do not attest an adversarial Python process or kernel execution.

The [final combined controls](../../../../artifacts/codebase_ir_terminal_bench/native-4096-head-and-guard-controls-20261004-03/receipt.json) passed: 71 checkpoint, 61 device and 67 tensor-guard cases, with zero failures, errors or skips. There were no fits or optimizer steps. One explicitly synthetic backward control tested adapter gradients. New controls cover paired finite-value and signed-zero mutations before and after a real CPU forward, replacement of anchor objects or payloads, checkpoint-byte parity and admission before allocation. The [preceding 191-case passing run](../../../../artifacts/codebase_ir_terminal_bench/native-4096-head-and-guard-controls-20261004-02/receipt.json) remains retained. The first attempt is retained with 145 passing and 39 failing cases; the failure was the device passing Torch's `OrderedDict` into the strict plain-mapping guard. The caller now normalizes its owned state mapping, preserving the tensor objects and pointers.

The [synthetic CUDA fixture harness](../../../ipfs_datasets/benchmarks/qualify_synthetic_4096_head_device.py) is prepared to compare complete 4096-input tensors, canonical decisions, all four logits and guard timing. Its [first attempt](../../../../artifacts/codebase_ir_terminal_bench/native-4096-synthetic-head-device-qualification-20261004-01/result.json) refused an undersized harness memory reservation before head execution; cleanup then encountered CUDA out-of-memory. The harness reservation was corrected. Its [second attempt](../../../../artifacts/codebase_ir_terminal_bench/native-4096-synthetic-head-device-qualification-20261004-02/result.json) timed out before admission. Neither qualifies CUDA head execution or a native guard speedup. The [ordinary postprocess closure](../../../../artifacts/codebase_ir_terminal_bench/native-4096-head-postprocess-closure-20261004-01.json) observed zero active leases after recovering the exited first attempt's lease.

The Leanstral service and full model weights were untouched. Its [capability gate](../../../ipfs_datasets/ipfs_datasets_py/logic/formalization/autoencoder/source_embeddings_4096.py) remains closed. Genuine untruncated native outputs and an operation-bound owner integration must precede real head training, model-quality evaluation, family-specific repository scans, signed dispatch and federated aggregation. The current source-span codec is LegalIR; the other IR families need their own task codec and qualification. All 32 production acceptance rows remain unchanged and open.
