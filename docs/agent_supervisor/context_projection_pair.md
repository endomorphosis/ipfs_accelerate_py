# Measure complete context before changing source views

The completed native GPT-6.1-sol pilot measured **313,979 tokens for legacy
metadata and 313,980 for the projected view**. The treatment passed Terminal
Bench; the baseline failed one speed check. This single independently planned
pair shows no total-token reduction and cannot attribute the different reward
to the representation. The deterministic Docker comparison below separately
isolates the amount of text replaced.

The October 13 prompt census found that the `largest-eigenval` supervisor input
already defers both public program bodies. Its inline `raw_sources` contains
three harness support files. A second source-omission profile would therefore
remove nothing on this fixture. The completed controlled comparison uses the existing
`common-bindings@1` lossless metadata projection with the exact source reader
in both arms.

The completed Docker experiment exposed **78,477 versus 79,362 UTF-8 bytes**,
885 bytes (1.12%) less. This counts the complete prepared router prompt and
every displayed source/catalog response once. The experiment uses an authored
provider hook, with no model calls or official task reward. It does not measure
total provider tokens. The [evidence bundle](evidence/context-projection-pair-20261013/README.md)
retains the captures' hashes, controls, owner replay and qualification records.

## What was replaced

Both arms run the existing `llm_router` preparation, isolated worker and owner
source service. The baseline metadata mode is `legacy`; the treatment is
`common-bindings@1`. Both use source profile `identity@1`. The projection factors
repeated capsule and admission fields into a shared table; the production codec
reconstructs the original transport exactly. The task context, source guidance,
support-file values, selected capsule content and coding reply contract remain
in the complete input.

| Captured UTF-8 bytes | Legacy | Common bindings |
| --- | ---: | ---: |
| Complete prepared router prompt | 53,933 | 53,048 |
| All default CLI stdout, including newlines | 25,429 | 25,429 |
| CLI stderr | 0 | 0 |
| One-pass combined exposure | **79,362** | **78,477** |

Factoring removes 1,840 bytes from capsule/admission fields and adds 955 bytes
of table, representation and instruction overhead. The selector includes this
overhead before choosing the projected input, and retains the original input
when the candidate does not improve its existing byte/proxy gate. That gate
does not establish a provider tokenizer's token count.

The two sessions execute the same 11 logical operations in 12 physical CLI
calls: discovery, source reads, exact expansion, an authored `idx` to `i` edit,
stale-read refusal, refreshed reads and restoration. Optional catalog discovery
costs 12,151 displayed bytes in each arm and stays in both totals. Exact-source
expansions and failed requests also stay in the totals. This rename exercises
the source workflow; it is not a solution of the benchmark instruction.

One frozen preflight precedes the two sequential sessions in a fresh Docker
container with separate owner/worker UIDs, read-only producer mounts, five CPUs,
12 GiB memory and networking disabled. Static indexing, capsules, world
construction and Doctor diagnostics run; checkpoint inference and full
supervisor START do not run in this offline experiment. There is no cold/warm
indexing-time or complete-session token claim.

## Strict replay of the captured comparison

[`context_projection_trace_comparison.py`](../../benchmarks/agent_supervisor/container_coding/context_projection_trace_comparison.py)
independently invokes the production projection and complete-input selector on
the captured baseline. The treatment must exactly match that reconstructed
input, including the workspace wrapper, reader guidance, suffix and reply
instruction. A caller cannot nominate arbitrary shorter text by supplying its
digest. The source manifest must bind the captured input files.

The comparator reuses the existing read/edit trace validation for complete
pagination, literal default CLI rendering, source hashes, edit postimages,
generation transitions, stale refusals, cleanup and separate native transport
accounting. Independent sessions generate different catalog identifiers; each
original catalog is replayed by its owner before the comparator normalizes only
enumerated generation-scoped identities. Source and capsule facts must still
match. Caller-supplied replay receipts are evidence, not authenticated handles.

All **289 focused regression tests passed**, including 52 comparator cases for
selection/fallback, changed input, wrapper drift, catalog identities, altered
facts, missing pages and unsupported authority or token claims. The initial
Docker probe failed on an incorrect assertion about a receipt field; its record
is retained alongside the corrected fresh run. No production fix was required
for that fixture mistake.

## Native qualification and next acceptance condition

A separate completed pair used independently initialized full supervisor
trials, the same pinned runtime, Source384 assets and extended formalization
budget. Both used `gpt-6.1-sol`, high reasoning, Codex CLI 0.160.0 through
`llm_router`. Full configuration comparison permits only the metadata view and
output-directory differences; both retained configurations remained unchanged.
Each arm made one planning and one coding invocation. Native cumulative usage
is counted once per invocation; cached input is already included in input.

| Native trial metric | Legacy | Common bindings |
| --- | ---: | ---: |
| Official reward | 0 | 1 |
| Input tokens, including cached input | 307,795 | 307,597 |
| Cached input tokens, subset of input | 250,112 | 250,112 |
| Uncached input tokens | 57,683 | 57,485 |
| Output tokens | 6,184 | 6,383 |
| Total native tokens | **313,979** | **313,980** |
| Planning tokens | 25,356 | 25,506 |
| Coding tokens | 288,623 | 288,474 |
| Agent setup seconds | 256.70 | 734.25 |
| Agent execution seconds, including planning/indexing | 291.14 | 345.89 |

The 198-token input reduction is offset by 199 more output tokens. Complete
native usage is observed, but dollar billing is not independently verified.
The baseline passed correctness checks and failed one speed check; the treatment
passed official verification. Both supervisors reported internal completion.
Internal completion is therefore insufficient to establish benchmark success.
No retry used verifier feedback to alter the frozen treatment inputs.
The retained declared-output observations lack final-file hashes, leaving
cross-arm output equality unverified. Future generic-task runs should retain
authorized output hashes before container removal.

The treatment's actual coding-input receipt selects `common-bindings@1` and
records **68,006 to 67,124 bytes**, a reduction of 882 bytes (1.30%). This is its
own original-versus-projected input; independent planning means cross-arm
prompt lengths are not a controlled byte comparison. The offline 885-byte
measurement uses a shared authored workload and remains separate. Neither
live model requested the optional indexed source reader; ordinary tool reads
remain included in the provider's native usage.

The treatment's CLI package download completed successfully after 466.976
seconds, accounting for much of its longer setup. No installation timeout or
intervention occurred. A hash-verified local copy of the same pinned package
was subsequently identified as an option for a future matched offline setup.
The [native evidence](evidence/context-projection-pair-20261013/README.md)
retains all executed attempts, stage timings, control bindings and usage scope.

The initial Grok baseline stopped at isolated credential readiness before text
generation, with `authentication_refused` and no reward. The prepared Grok
treatment was not executed against that unavailable route. This attempt remains
in the experiment record. Both pinned Grok 1.0.46 and installed 1.0.52 rejected
fresh isolated credential copies; changing the binary alone did not repair the
route. Host credentials were unchanged. The separately declared GPT-6.1-sol
fallback pair above completed; it is not mixed with Grok usage.

Both native trials consumed the same Source384 checkpoint and decoded four
function candidates, all marked `fail_open_source_contract_unsupported` and
unverified. IntentIR returned `fail_open_no_checkpoint`. The Source384 mode was
`pinned_parent`, with zero target-training steps. These runs qualify the full
supervisor's selected metadata profile, not a fully trained multi-IR system or
verified source proof coverage. Connecting a trained IntentIR checkpoint and
covering these numerical source contracts remain separate work.

The measured reduction so far comes from repeated metadata. Wider savings
require fewer unnecessary reads or smaller relevant selections, with all
expansions and repairs charged. The
[repository-wide view plan](reversible_codebase_views_plan.md) separately tracks
exact restoration and mapped edits. This experiment establishes neither
source-equivalence proofs nor the value of target-trained CodebaseIR or other
IR checkpoints.

## Next reductions to qualify

The content-free
[follow-up census](evidence/context-projection-pair-20261013/investigation/next-context-opportunities.json)
identifies exact repetition that the current projection does not cover:

| Candidate | Encoded bytes before replacement overhead |
| --- | ---: |
| Second occurrence of an identical policy value | 1,783 |
| Shared constant fields across eight pack references | 1,014 |
| Escaping overhead from canonical JSON stored inside strings | 743 |
| Two extra copies of the 716-byte public instruction | 1,432 |

These estimates overlap; they must not be added or reported as token savings.
Start with exact policy and pack-field factoring, preserve the entire original
transport through inverse reconstruction, and count all table/instruction
overhead in the complete input. Nested JSON and instruction reuse require
separate coverage of their serialization and consumer contracts. The existing
source/candidate readers do not provide exact immutable lookup of all native
intent-world, retrieval-summary or pack snapshots, so these contexts cannot
simply be replaced by unresolved references.
