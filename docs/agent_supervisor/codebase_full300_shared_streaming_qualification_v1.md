# Full 300 shared inventory and streaming inference

The new shared scan defaults to optimization enabled and supports explicit `optimized=False`. It sends one shared inventory per numerical request and streams restored targets into feature rows. On the fresh 300-entry CPU fixture, numerical requests fell from 14 to 5, input bytes fell by 95.5%, numerical child time fell by 58.6%, and peak individual numerical child RSS fell by 41.6%. All 294 eligible rows and 588 projection records were exactly equal across shared default, shared reference and legacy default. These measurements describe this fixture; `throughput_qualified` remains false.

This workload has 53 structural input features and an 8-wide latent. It does not qualify a trained semantic 8D source head, trained 384D/768D/4096D CodebaseIR heads, CUDA, formal proofs, signed dispatch or a full working-repository scan. Those gates remain in the [four-head integration note](codebase_larger_head_native_owner_integration_note.md) and [Repository Proof Index milestones](../architecture/repository_proof_index_and_codebase_ir.todo.md).

Shared default recorded 8.7% less total time for those seven phases than legacy default and 40.9% less than shared reference. Child elapsed includes startup, validation, inference and cleanup. Each mode processes two parent pages and resumes the remaining three pages in its own fresh process. The six nonnumerical dispositions are one unindexed entry, two opaque entries, one parse failure and two unsupported targets. Both shared modes retain one restored target at a time. Their 429,263,547 logical restored bytes are cumulative accounting, not simultaneous retention.

The [shared transport](../../../ipfs_datasets/ipfs_datasets_py/logic/software_contracts/codebase_resume_shared_targets.py) detaches only the manifest and publication receipt. It binds the complete inventory and global membership, full original target/source digests, compact bytes and shared bytes. The [worker](../../../ipfs_datasets/ipfs_datasets_py/optimizers/logic_theorem_optimizer/codebase_inventory_shared_worker.py) restores each row and independently replays source, AST/provenance, authored contracts, native lowering and complete canonical target equality before feature extraction. All rows must pass before Torch is imported. It releases successful native replay frame references; reference mode explicitly collects legacy validation cycles once per row. Default requires no forced collection.

The captured inventory ceiling is 512; this campaign exercised 300. Rows remain bounded by 64 per request, full and compact targets by 4 MiB, shared declarations by 16 MiB, native root manifests by 4 MiB, stdin by 32 MiB and stdout by 16 MiB. Feature cells have an independent 262,144 ceiling; root limits restrict a request to at most 65,536 cells. Each numerical child retains CPU float64, one thread and the existing 1 GiB sampled RSS ceiling. Shared manifest/receipt parse counters count initial declaration parsing; reference performs additional native parsing during its two replays per row. Matrix counters count the final assembled matrix; the row feature helper still runs once per streamed row.
