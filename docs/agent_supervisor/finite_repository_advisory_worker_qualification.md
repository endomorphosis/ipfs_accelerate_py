# Advisory CodebaseIR training joined to native worker publication

This additive experiment joins explicit source-bound CodebaseIR adaptation,
mathematical AST lowering and a retained reviewed proposal to the existing
finite repository worker loop. The implementation is in
[the joined harness](../../benchmarks/agent_supervisor/container_coding/finite_repository_advisory_worker_experiment.py),
[the preparation and replay hooks](../../benchmarks/agent_supervisor/container_coding/finite_repository_advisory_worker_support.py)
and [the offline container wrapper](../../benchmarks/agent_supervisor/container_coding/run_finite_repository_advisory_worker_docker.py).
The [completed native execution](../../../../artifacts/codebase_ir_terminal_bench/finite-advisory-worker-qualification-20261002-04/native/result.json)
passed in 522.178398 seconds with 32 actual attempted training epochs. This is
a bounded authored fixture; its retained evidence and limits are recorded below.

The fixture commits ten Python files before supervisor initialization or source
capture. Four authored selections use the existing source-bound structural
feature adapter: two training units and fixed tuning and canary units. The
known offset-two variant is already in the training cohort. This is a
transductive fixture compatible with the Terminal Bench runner, not a held-out
public Terminal Bench corpus evaluation or a learned formal decoder.

Root fitting is an explicit preparation operation with sixteen epochs. Frozen
replay and advisory capacity previews then compare finite source facts and
original clause outcomes across model-off, trained and frozen modes. The
signed worker admission retains its qualified model-off semantics. Model
scores, structural vectors and generic lowering proofs cannot grant execution,
omit either original task, or complete a native task.

The owner retains and verifies the reviewed proposal and generated replacement
artifact. A separate readonly worker descriptor binds those exact bytes to the
original signed admission and ready residual task. The real native owner
claims, validates and completes the prerequisite; the actual isolated worker
claims the residual, edits only the permitted source, runs public checks,
publishes a two-parent Git merge and completes through native claim/lease/fence
validation. Proposal verification is evidence linkage, not an extension of the
signed worker authority profile.

Advisory model and generic lowering artifacts have native preparation checks
and retained-byte observations after STOP. The existing final spawn fence binds
the finite admission, source, public handoff and task authority. It does not
bind these additional advisory artifacts. A separate typed admission profile
and callback-mutation qualification are required before claiming advisory
artifact closure at actual process birth; that exit remains open here.

Successor work waits for native STOP, process cleanup and the fixture's explicit
cleanup of the observed allocated worktree. That cleanup is not automatic
worker crash recovery. A fresh independent fixture profile binds the actual new
Git baseline while preserving the old signing history. Native source generation
and invalidation precede sixteen child training epochs with the frozen parent
basis, Adam lineage and unchanged tuning/canary ancestry. Fresh Lean compilation
checks the supported mathematical AST lowering and requested integer-offset
identity against the newly captured native IR. Parser correctness, CPython
semantics and universal repository correctness remain unproved.

Cold verification has two distinct scopes. A fresh process reopens the original
catalog and registry at the exact retained successor head and verifies frozen
features and lowering without fitting or promotion. Separately, a fresh catalog
captures the published repository and compares explicitly named finite source
and clause outcomes. Its generation-one head cannot replace the original
successor generation in a frozen context or proof record.

Complete producer records and owned artifact bytes are packaged losslessly into
DuckDB and DuckLake metadata, including repository inventory, AST, imports/calls,
frontend dispositions, contracts, vectors, model lineage, proof artifacts,
proposal/handoff linkage, native tasks, claim/completion/public-check evidence,
publication, lifecycle and cleanup. Fresh-process readback must reconstruct the
complete records. Counts are derived from this run rather than inherited from
an earlier fixture.

The full population exceeded the existing 64 MiB native sink bound in the third
development run. The additive
[sharded metadata assembly](../../benchmarks/agent_supervisor/container_coding/finite_repository_sharded_metadata.py)
partitions canonical rows deterministically, preserving family order and global
ordinals. Each independently native part is limited to 32 MiB and 32,768 rows;
the original 64 MiB sink, 256 KiB row, 49,152-byte chunk, packet and process
limits remain unchanged. The global profile permits at most sixteen parts,
512 MiB of payload and 524,288 rows. Its manifest binds each native manifest,
source snapshot, family span, complete export and packaged/producer digest.
Complete producer records have a separate bounded recovery artifact. Native
part readback and a subsequent genuinely new global process verify exact
reassembly, including chunks spanning parts. This assembly is not one native
transaction and does not qualify crash-safe global publication.
Each legacy native part retains its 60-second fresh-process timeout. The new
global assembly has an explicit 300-second restart cap; it does not replace
the native part policy or the wrapper's separate 900-second total envelope.

Run the new wrapper from the accelerator checkout with the accelerator,
datasets and kit checkouts on `PYTHONPATH`:

```bash
python -m benchmarks.agent_supervisor.container_coding.run_finite_repository_advisory_worker_docker /absolute/fresh/output
```

The wrapper snapshots selected package sources into readonly mounts, retains
actual offline dependency observations, uses the qualified root-owned launchers
and separate owner/worker UIDs, and removes the container before releasing its
host reservation. The envelope is twelve CPUs, eight GiB and 512 PIDs; the
complete native experiment has a separate 900-second timeout. Existing
per-preparation deadlines, process policies and host-pressure gates are
unchanged. Container limits are aggregate limits, not per-worker kernel ceilings.
No reviewed-proposal origin attestation or inaccessible signing-key proof is
inferred from its same-UID generation subprocess.

Finite observed loss improvement is a measurement. It is not a proof of
optimizer convergence, generalization, semantic decoding or official benchmark
reward. Production activation and the broader implementation-plan exits remain
open.
