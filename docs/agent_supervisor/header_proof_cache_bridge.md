# Scoped native header proofs in the Doctor cache

The reviewed header bridge can admit an actual native local lemma to an existing
`DoctorProofCacheGate`. It first reruns the pinned native kernel against the
original sealed proof and current preparation. The generic receipt retains the
local theorem, its assumptions and any open SecurityIR obligations. Its assurance
is `KERNEL_VERIFIED`; it cannot complete a task or authorize source mutation,
execution or a whole-program claim.

This is an explicit host API. Terminal does not automatically construct or select
this bridge, and actual Terminal accepted-receipt coverage remains unmeasured.
Required facts remain inline until a current host binding and bounded expansion
interface are qualified.

## Typed local scope

`LocalProofScope` has a closed versioned schema. It retains the native theorem CID,
obligation, property, consequence, proof scope, premises, assumptions and residual
obligation IDs. `ScopedProofReceipt` uses `proof-receipt@2`; the existing
`proof-receipt@1` constructor and canonical bytes remain unchanged. The standard
`ProofReceipt.from_dict` dispatcher preserves and validates the complete `@2`
body. Cache restart therefore retains its typed conditions.

Local assurance and completion are separate decisions. A proved `@2` receipt can
satisfy the kernel-assurance requirement for its exact local lemma, while
`satisfies_completion` is always false. The receipt's completion reference says
`conditional_local_proof_cannot_complete_task`. Every local-scope authority flag
is fixed false, even when no residual IDs are present.

The public goal-completion evaluator honors that decision. Flat formal claims,
policy outcomes, plan proof preconditions, implementation-proof bindings and
code-claim/cache-hit projection refuse this scoped receipt because their output
contracts cannot retain and discharge its complete conditions. A future
scope-aware consumer needs an explicit contract and evidence for those conditions;
copying them into metadata does not authorize a flat satisfied claim.

## Import with existing owners

[`import_header_proof_to_cache`](../../ipfs_accelerate_py/agent_supervisor/runtime/doctor_header_cache_bridge.py)
requires these keyword arguments:

| Argument | Independently admitted input |
| --- | --- |
| `prepared` | Current complete preparation from `prepare_header_contract_proof` |
| `hammer` | Existing native Hammer, SQLite owner and both current trusted pins |
| `custody_ref` | Original typed sealed key-custody reference |
| `expected_key_id` | Independently expected complete Doctor key identity |
| `gate` | Existing native Doctor gate and its original formal-cache owner |
| `expected_owner_path_sha256` | Independently expected canonical DuckDB path digest |

The bridge constructs no owner, discovers no database locator and performs no
provider or model call. Host profile identities and path hashes are expected
inputs, rather than authentication of arbitrary caller-supplied preimages.

Admission verifies the exact canonical preparation, original sealed proof and
solver/kernel lineage in the native owner, then performs fresh native kernel
replay. It reviews the actual header adapter's command configuration, executable
digests, requests, outputs and transcript identities. The native kernel label and
the full key's kernel-verifier identity have an explicit reviewed correspondence;
neither is substituted for the other. Boolean acceptance fields or a valid HMAC
envelope alone cannot mint generic evidence.

The original contract CID remains the logical source premise. The bridge checks
the reviewed public AST-observation projection and its exact inverse against
current source. The projection retains its distinct artifact CID, and the general
private-material classifier stays unchanged. Native AST-index and composition-index
namespaces are checked separately.

Evidence refers to the original sealed kernel receipt and derives exactly
`KERNEL_VERIFIED`, never `ATTESTED`. Native theorem assumptions remain typed.
When SecurityIR bindings exist, independent compilation checks the current
declaration/artifact identities and retains the actual generated obligation IDs
as residuals. Open frontier descriptions remain visible; they are not invented
obligation IDs and no SecurityIR obligation is discharged by this import.

The receipt is deterministic for the same original proof, preparation and current
implementation. It uses the canonical tactician receipt's content identity and
the sealed custody body CID. Persisting an identical custody body in a different
row does not change the generic receipt or trigger equivocation. The handle still
retains and checks its exact original custody reference.

## Recheck before reuse

The returned `HeaderProofCacheAdmission` exposes immutable detached `key` and
`receipt` snapshots. Its `accepted` and `stored` values describe historical
admission; they do not assert current eligibility. Use its bound
`revalidate_for_render()` and `revalidate_for_commit()` methods before reuse.
A raw gate lookup or a serialized acceptance flag does not replace those checks.

For host integration, `assert_bound` checks exact gate/analysis objects and
independently expected key/receipt/path identities without storage I/O.
`assert_cache_binding` performs the cache joins while the host separately joins
the signed analysis. `assert_current` executes the retained guard without kernel
execution. Recursive same-handle currentness or stage operations refuse.

Each stage checks current signed source, retained wrapper, AST translator and
SecurityIR compiler implementations, profiles, both executable pins, requested
bounds, original sealed proof/custody lineage and the
exact deterministic generic receipt. It fences the same native/cache/state
objects, canonical owner paths and file device/inode. Durable quarantine and
tombstone state are consulted together before final source and owner checks.
The current bridge and receipt-codec file digests are included in the receipt and
rechecked at each stage. Source or implementation drift visible during the last
generic consultation refuses the result.

Render/commit checks reload the original custody and lineage without rerunning
the kernel. After an explicit host restart, independently rebuild current
preparation and reopen the same admitted owners with the original private seal
key; importing again performs fresh native kernel replay. The bridge supplies no
owner-opening factory and exports no private seal key.

These checks are sequential and grant no atomic owner lease. Native gate
bookkeeping can write its existing owner, including durable refusals or
equivocation. A failed final check returns no accepted handle or stage result;
it does not roll back earlier native writes. Requested CPU/memory/network bounds
are inputs, without certification of OS enforcement. Bounded receipt bytes do
not bound native lineage-prefix work or arbitrary executable filesystem effects.

A later emitter/codec upgrade changes the deterministic receipt body but does
not itself change the native key. Reimport under that unchanged key can correctly
trigger equivocation. Plan a separately admitted versioned profile/key migration
for upgrades; do not clear quarantine or replace the original owner to hide this
identity change.

## Qualification and remaining integration

Authored tests use actual temporary native SQLite/HMAC and DuckDB owners with
explicitly mocked solver/kernel transcripts. They qualify contract joins,
restart, drift, denial and owner handling, without proving the authored theorem.
A separate case executes actual installed Lean/Z3 on authored header source,
imports after fresh kernel replay, checks render reuse, explicitly reopens the
owners and verifies another fresh kernel invocation. Qualification records keep
these evidence classes separate.

The programmatic formal-status census can retain and count the canonical scoped
receipt with all authority flags false. Its current-binding probe is a host
admission. The [typed Terminal host binding](terminal_header_proof_admissions.md)
now carries the bound handle and independent key/receipt population through
task/source/context checks and both observation passes. It preserves current
native custody, implementation, profile and executable checks. Supplying only
raw keys and a gate refuses scoped receipt coverage in that host route. Actual
live accepted Terminal coverage remains unmeasured.

Then measure the exact accepted population and repeated-status closure. Preserve
property, verdict, assurance, assumptions, source/dependency digests, residuals
and unresolved frontiers in any replacement. Qualify bounded source/receipt
expansion and native lookup cost, census the complete coding input, and only
then run a matched trial using total native planning/coding/lookup/repair tokens
and reward. The updated runtime source inventory contains the bridge, scope codec
and changed consumers; historical archives remain historical evidence.

This phase changes no embeddings, checkpoints or training. LegalIR, SecurityIR,
CodebaseIR and IntentIR retain separate family/schema/version/decoder-task
inventories and parallel 8D/384D/768D paths.
