# Finite repository admission qualification

The additive [finite repository admission boundary](../../ipfs_accelerate_py/agent_supervisor/runtime/finite_repository_admission.py)
joins current-source finite observations to an independently signed local task
contract. It retains every original administrator task and the existing native
completion guards. This is a local model-off integration increment; native
worker launch, multi-task publication and general source semantics remain
separate milestones. All 32 production acceptance tasks remain open.

The [retained native fixture](../../../../artifacts/codebase_ir_terminal_bench/finite-admission-qualification-20261002-04/result.json)
completed in 50.720 seconds. The [current boundary suite](../../../../artifacts/codebase_ir_terminal_bench/finite-admission-tests-20261002-04/current-summary.json)
passes all 38 cases in one fresh run, with no failures, errors or skips. Its
47 selected critical source paths remained unchanged. Retained source copies
are sequential observations rather than an atomic checkout or process-origin
attestation.

The [compatibility ledger](../../../../artifacts/codebase_ir_terminal_bench/finite-admission-qualification-20261002-04/test-ledger.json)
separately records 119 passing local-admission/finite-service cases and all 21
current capacity cases with passing latest outcomes. The capacity run retained
three native lease timeouts; only those cases were retried, and all three passed
without changing the sampler or pressure gates. These runs are separate from
the clean 38-case boundary run. The [review record](../architecture/repository_proof_index_and_codebase_ir.finite_admission_review.json)
pins this increment's selected sources, documentation and retained results.

## Declaration and evidence

`author_finite_repository_declaration` signs the full original local manifest,
complete source generation, exact planning request, original prompt bytes,
canonical IntentIR, both reviewed operations, sealed Python/Lean tool policy and
explicit clause-to-native-task bindings. The selected feature identity is
`model_off`; training and inference are absent from this profile. The original
manifest retains the outputs, dependencies and public acceptance commands.

`admit_finite_repository_plan` independently prepares fresh finite observations
and the existing capacity preview. It reconstructs the complete clause/fact
partition, source lowering, mathematical-model artifacts and original local
graph contract before signing the resulting context. A caller-supplied preview,
fact label or task subset cannot replace these owned observations. Boolean flags
use exact canonical types; owner signatures cannot turn numeric `0` or `1` into
authority flags.

The reader explicitly requires `finite-integer-capacity-bound-plan-preview@2`
and its complete model-off validation policy, including empty numerical
verification points and false authority flags. Changed policies, extra fields
or a later capacity schema cannot silently enter this profile.

The bounded facts retain `BOUNDED_OBSERVATION` authority. A Lean theorem for the
integer model remains a theorem for that model. Neither result establishes
unrestricted Python behavior or permits task omission. A no-work observation
retains the complete signed graph but receives `planning_permitted=False` and
no local admission; materialization refuses it.

## Native commit and historical replay

`materialize_finite_repository_plan` reobserves the frozen source/context and
calls the existing native local materializer inside one `IntentRepository`
transaction. Every task retains its signed `local_planning_contract`. The plan
stores a reference to the complete immutable finite admission outside the
worker repository. Final source, Git, catalog/CAS, tool and artifact fences run
after signing and materialization callbacks and before transaction commit.
Late mutation rolls back objectives, goals, plans and tasks together.
The retained execution uses an exclusive native DuckDB file; it does not
exercise a live Quack server or a typed remote worker claim.

`verify_finite_repository_admission` checks historical signed/artifact integrity
without source observation, proving, training or a current permission claim.
It remains owner-local: the existing active-profile loader requires the local
profile/key state, and retained artifacts plus selected producer/tool bytes
must remain available. This is not portable offline archival verification.
`verify_current_finite_repository_admission` is a separate fresh native check;
an old historical receipt cannot establish that its source generation is current.

The new profile accepts original local manifest versions 1 through 3 and
explicitly rejects version 4. The retained joined fixture exercises version 1;
it does not independently qualify the new finite join for versions 2 or 3.
Existing manifest schemas and owner guards are unchanged.

## Retained native fixture

The [new experiment](../../benchmarks/agent_supervisor/container_coding/finite_repository_admission_experiment.py)
captures an isolated seven-file Git repository with `calc.py::increment`, a
same-name `decoy.py::increment`, a consumer and supporting unit, a dynamic unit
outside the integer profile, and two public checks. The dynamic unit remains in
the captured AST inventory and its integer lowering is refused. Opaque entries
and linked Git worktrees remain outside the existing source-custody profile.

The complete instruction requires an exact integer and `n + 2` for the five
explicit inputs `[-2,-1,0,1,2]`. The initial body returns `n + 1`, so the type
clause is boundedly observed and the offset clause remains residual. Both
administrator tasks are committed. The public type prerequisite may complete
only after its actual owner-signed validation; the independently executed
offset check fails. These are native owner operations without a worker launch.

An explicit fixture edit then changes the body to `n + 2` under the same Git
HEAD. Old current verification rejects; the historical parent still replays.
A newly captured generation and signed declaration produce a no-work review,
which cannot materialize an empty task grant. A separate cold catalog capture
and fresh native observations must agree on source/domain identities and finite
clause outcomes. Their complete generation envelopes remain distinct.

The [fresh-process replay](../../../../artifacts/codebase_ir_terminal_bench/finite-admission-qualification-20261002-04/fresh-process-replay.json)
resolves the complete admission from the native plan reference and retains the
