# Signed selected context at the Terminal coding router

The [signed Terminal profile](signed_terminal_source_scope.md) keeps complete
public inputs beside a bounded semantic/vector selection. The coding-router
handoff now independently joins that declaration to its compiled semantic
payload and the embedded signed manifest. This extends the existing public
instruction route, without creating a native source grant or another owner.

## Public artifact and compiled selection

Owner preparation uses `supervisor-public-instruction@5` when the independently
signed canonical profile is `terminal-public-task-profile@4`. The new artifact
retains `terminal_task_profile` alongside the existing public manifest, exact
selected instruction and task identity. Its content identity and launch digest
pin the declaration; the manifest signature independently binds its canonical
profile SHA. Existing instruction artifact versions keep their own shapes.

The worker loads the explicit artifact, verifies its public signature and task,
and replays complete originals in the canonical repository and matching linked
allocation. It then checks the actual compiled semantic chunks and retained
producer artifacts against the signed selection: exact selected paths, program
paths, required raw originals, source SHA/raw CID identities and combined byte
bounds. The canonical profile is required raw support. Unsupported or incomplete
selection refuses. A generic semantic payload is not sufficient evidence of a
signed declaration. A profile downgrade is checked against actual signed PROFILE
bytes independently of the prompt's optional metadata.

The selected ceiling remains 61 ordinary inputs plus three generated supports,
64 total files and 1,000,000 original per-path bytes. Complete public-instruction
source replay keeps its independent 4,000,000-byte bound. A smaller semantic
selection cannot bypass that full-source bound or the original task effects.

## Closing replay and observations

The actual `router_implementation_runner.run()` coding route repeats the signed
selection/compiled-payload/full-source join after provider initialization and
source-descriptor checks, immediately before `generate_text`. Its returned block
and receipt must still equal the earlier admitted values. A selected or omitted
source change in either checkout prevents generation. These are sequential
observations, without an atomic filesystem writer lease or rollback guarantee.

A successful scoped worker receipt retains
`terminal_semantic_scope_dispatch_rechecked=True` and
`supervisor-public-instruction-inclusion@5`. Its nested
`terminal-signed-semantic-worker-inclusion@1` summary binds manifest, profile,
declaration, frontier, observation, semantic scope/root and payload identities,
with counts and bounds. It contains no complete source map or source bodies.
Native claim, allocation and process-identity verification flags remain false,
as do proof, execution, completion and omission authority. The enclosing
instruction receipt separately records public signature and source freshness.

Historical model-input audit accepts this version explicitly and reproduces its
scope summary from the retained signed declaration, baseline Git objects and
producer artifacts. It compares the entire deterministic summary and recorded
closing observation. Historical reconstruction does not repeat live dispatch or
establish that a current native claim remains valid. Existing instruction
minification retains its exact inverse with this new inclusion version; it does
not remove the required profile or source facts.

## Archive compatibility

`terminal-router-worker-capability@4` pins 46 source files, including 14 additional
profile, scope, preparation, public-instruction, bundle, compiler and daemon
owners. It explicitly declares the task-profile and semantic-scope versions and
retains worker child custody `@1`. A fresh archive must match the executing
installer's reviewed bytes and feature labels before Harbor preparation or
deployment. Missing, stale, duplicated or falsely relabelled owners refuse.

These pins are a listed compatibility contract, not a complete import-closure
or executable-runtime attestation. The archive builder already includes runtime
Python sources recursively. Hermetic archive tests can verify extracted source
hashes and run the standalone profile producer; they cannot certify an entire
installed coding worker. Rebuild and pin a complete deployment archive before a
new live experiment. Older frozen archive evidence retains its original meaning.
