# Check metadata compression before a provider run

The [complete-token plan](terminal_token_metadata_plan.md) uses a census before
spending on a new benchmark comparison. The census measures the complete coding
input and its exactly restorable metadata view. General planning and
`llm_router` remain part of the live benchmark.

## Current runner stop point

[`router_implementation_runner.py`](../../ipfs_accelerate_py/agent_supervisor/runtime/router_implementation_runner.py)
accepts `census_only=True`, exposed as `--semantic-metadata-census-only`.
It requires `common-bindings@1` on the original semantic coding transport `@1`.
The owner supplies the same native stdin context, canonical repository,
allocated worktree and bound Doctor/public-instruction artifacts as for coding.

The runner executes the existing current semantic encoder, common Git owner,
workspace, artifact and credential-isolation checks. It constructs the original
and candidate inputs with the same literal wrappers and reply instruction.
It then returns a dedicated `router-semantic-metadata-census@1` observation
before provider discovery, allocation or invocation. This output cannot serve
as a coding acknowledgment, validated result or task completion.

[`semantic_metadata_census.py`](../../ipfs_accelerate_py/agent_supervisor/runtime/semantic_metadata_census.py)
independently restores the original representation, checks the fixed projector
and verifies the complete-input selection. Its closed report contains hashes,
capsule/admission counts, captured and referenced source-group counts, fixed
shared field names, input byte/proxy counts and selected/fallback status.
Task/root/scope identities are hashed. Source text, paths, unknown field names,
common values and plan/provider bodies remain with the existing owner.

Both complete inputs must fit the fixed 256,000-byte runtime bound and the
candidate must actually be selected for `eligible_for_matched_input_comparison`
to be true. This flag describes representation eligibility. All proof,
freshness, omission, dispatch, execution, completion and publication authority
remain false. The named `utf8-bytes-ceil-div4@1` proxy is byte-derived;
provider tokens and complete-run savings remain unmeasured.

## Administrative public-task preparation

A census of current public source can use a freshly admitted, explicitly
authored administrative graph. The preparation must retain the current signed
declarations, source inventory, native owner materialization and actual daemon
context construction. Its graph provenance and index configuration are part
of the result. Historical admissions or database files cannot substitute for
current native preparation.

This scope differs from a live input produced after LLM planning. A source
census with an authored graph and deterministic index does not reproduce a
previous Source384 run or measure the cost of planning. The native owner may
process declared public inputs to build capsules; diagnostics export only the
closed metadata report. Hidden evaluators and solutions are outside this
preparation.

## Qualification and trial decision

Check exact restoration, complete bounds and actual selection before a pilot.
Report fallback or a small input reduction as observed; neither establishes
total token savings. The runner qualification compares its census digest with
the normal coding runner's delivered input while spies forbid all provider
operations. Drift, foreign workspace, inherited credentials and invalid
instruction bindings are negative controls.

A later live comparison freezes both arms on one new runtime, retains planning
and coding through the router, and fixes original `@1` transport and the reply
schema. Fixed controls alone do not establish identical generated plans.
Keep substantive native inputs and counterfactual digests visible in the
comparison; call an exact one-factor input comparison only when those checks
pass. Count every retained session and repair cost, including failed attempts,
and preserve unknown usage.
