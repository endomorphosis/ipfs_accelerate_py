# Verified Residual Intelligence Foundry plan

Program identifier: `agent-supervisor-verified-residual-intelligence-foundry-v1`

Primary subsystem: `VerifiedResidualIntelligenceFoundry`

Task prefix: `VRIF-`; root objective: `VRIF-G000`; plan revision:
`VRIF-PLAN-R1`; campaign branch:
`codex/verified-residual-intelligence-foundry-v1`.

## Outcome and invariant

The foundry identifies the bounded reasoning left after deterministic
analysis, cached evidence, verified procedures, and architecture
simplification. It converts recurring residuals into compact, calibrated,
abstaining local specialists whose results remain proposals until an admitted
independent validator accepts them. It extends existing supervisor authorities;
it does not replace context compilation, planning, proof, procedure,
architecture, provider, model-serving, checkpoint, resource, worktree,
receipt, CLI, MCP, or control-service systems.

The cascade is fixed:

```text
exact cache
  -> verified procedure
  -> deterministic rule
  -> local linear expert
  -> local ranker
  -> local structured specialist
  -> local general model
  -> remote standard model
  -> remote strong model
  -> human review
```

The output of every learned stage has `candidate_only = true`. The production
path transmits a bounded typed result; optional prose is generated only after
the typed decision exists, for human review or an explicit request, under its
own token budget.

The non-compensable invariants are: zero model-created authority; zero
model-created policy permission; zero model-created confirmation; zero
model-created proof acceptance; zero model-created completion; zero
simulated-as-live evidence; zero stale checkpoint promotion; zero training on
unadmitted data (`zero training on unadmitted data`); zero private-data leakage;
zero hidden validation reduction;
zero autonomous lowering of abstention thresholds; zero production
exploration; and zero false completion.

## Authority and persistence architecture

DuckDB is the authoritative store for objectives, goals, dependencies, task
revisions, attempts, claims, leases, fencing, validations, evidence, completion
receipts, corpus-admission decisions, training epochs, routing receipts, and
promotion state. Quack is the authenticated loopback state-owner transport for
parallel scheduler processes. All mutations use typed service operations,
idempotency, an exact expected revision, lease and fence checks, resource
budgets, and audit receipts.

DuckLake is a non-authoritative, append-oriented projection for historical
analysis, paired benchmarks, aggregate metrics, and compact public reports. A
DuckLake row cannot make work ready, authorize an effect, accept proof, promote
an expert, or complete a task or goal. Markdown files are sealed bootstrap and
human-readable exports after database materialization. Quack identity,
payment/network identity, model confidence, and task-board status are never
authority.

The existing canonical owners remain in place:

- content identity, immutable artifacts, worktrees, resource scheduling,
  leases, fencing, receipts, checkpoints, providers, hardware qualification,
  model serving, batching, context compilation, procedure compilation, proof
  verification, validation, and control operations;
- SemanticCompressionHarness and SemanticCompressionGovernor for context
  sufficiency, not expert validation;
- AdaptivePlanner, IncrementalVerificationPlanner, IncrementalProofSealer, and
  the actual prover for planning and proof authority;
- Adversarial Assurance for mutation campaigns; and
- the learning-checkpoint contract for exact lineage, never promotion
  permission.

Missing optional authorities produce typed capability blockers local to their
dependent integration. Independent work continues. A missing required
authority produces a typed blocker rather than a substitute subsystem.

## Data admission and current PGIR no-go

No source row or execution history is training permission. Every training
request must name one admitted `TrainingCorpusAdmission` binding source and
transformation rights, privacy and tenant scope, retention, corpus/split and
holdout roots, deduplication, a passing leakage audit, tokenizer/compiler
identities, independent label producers, negative-example policy, adversarial
partition, and environment.

The current proof-grounded IR (PGIR) freeze/no-go remains binding. Its lack of
rights-admitted materialized rows, complete holdouts, tokenizer, qualified
checkpoint, or publication authority is not bypassed. Until a corpus gate
passes, corpus, deterministic baseline, evaluation, and runtime-contract work
continues but any training request returns `training_unavailable`. No fake
checkpoint or simulated promotion is created.

Permitted candidate sources are only first-party supervisor trajectories with
clear rights, synthetic fixtures, adversarial mutants, mechanically generated
counterexamples, explicitly authorized private deployment data, documented
human-reviewed examples, or public datasets with exact training-compatible
licenses. Credentials and private chain-of-thought never enter training;
proof witnesses never enter public artifacts; tenant-private data never trains
a shared expert without explicit declassification.

## Residual contracts

The inventory records each accepted and rejected model invocation's stage,
task family, question and input/output contracts, context size, provider,
model, tokens, latency, cost, validation, terminal outcome, deterministic and
procedure answerability, smaller-model answerability, decision relevance, and
authority. Families share input semantics, output semantics, risk, authority,
validation, error, and abstention behavior; prompt or embedding similarity is
insufficient.

The closed taxonomy is:

```text
TASK_CLASSIFICATION                  RISK_CLASSIFICATION
EFFECT_CLASSIFICATION                AUTHORITY_REQUIREMENT_CLASSIFICATION
CONTEXT_SUFFICIENCY                  EVIDENCE_RANKING
PROCEDURE_MATCHING                   PLAN_BRANCH_RANKING
TEST_SELECTION                       PROOF_SELECTION
FAILURE_ATTRIBUTION                  RETRY_OR_ESCALATE
CACHE_REUSE_CLASSIFICATION           MERGE_CONFLICT_CLASSIFICATION
PATCH_TEMPLATE_SELECTION             PROCEDURE_HOLE_FILLING
PATCH_SKETCH_GENERATION              LEMMA_SUGGESTION
TACTIC_SUGGESTION                    COUNTEREXAMPLE_EXPLANATION
GOAL_REFINEMENT_CANDIDATE            DOCUMENTATION_CLAIM_CLASSIFICATION
HUMAN_ESCALATION_CLASSIFICATION      NOVEL_UNBOUNDED_REASONING
```

`ResidualTaskInput` binds the task family, question and repository/objective/
task/policy/context identities, compact features, allowed outputs, risk,
validation policy, and token budget. `ResidualTaskOutput` binds one allowed
output class, a closed structured payload, score, calibration group,
abstention, reason codes, evidence references, and `candidate_only`.
Unknown fields, duplicate JSON keys, out-of-grammar values, arbitrary shell,
authority-shaped output, completion-shaped output, and oversized results fail
as `invalid_output`; prose is not recovered heuristically.

## Expert forms, calibration, and routing

Implementation order is exact lookup, declarative rule, linear/logistic model,
small ranker/encoder, constrained structured decoder, parameter-efficient
adapter, quantized local general model, then remote routes. A larger model is
eligible only when current held-out evidence demonstrates a routing-changing
quality gain for the exact family and risk group.

Every expert has a closed input/output schema, grammar, enumerations, maximum
output length, abstention representation, validation policy, family boundary,
risk ceiling, hardware/runtime requirements, and privacy route policy.
Disposition is one of `ACCEPT`, `ABSTAIN`, `REJECT_INPUT`,
`OUT_OF_DISTRIBUTION`, `CAPABILITY_UNAVAILABLE`, or `VALIDATION_REQUIRED`.
Calibration is grouped by family, repository, language, framework, risk,
model, quantization, hardware, and context tier; there is no global threshold.
R4/R5 outputs remain proposal/ranking tier regardless of accuracy.

OOD signals can include family/embedding distance, feature-range and schema
violations, unknown repository/effects/authority, disagreement, missing
calibration groups, and incomplete context. OOD is advisory unless policy
admits it; separate high-risk contract checks conservatively abstain.

Routing rejects candidates outside a task-family or risk ceiling, unavailable
hardware, private-to-unauthorized-provider transfers, absent validation,
simulation, and capability inferred from importability. Each receipt preserves
all candidates, hard rejections, selected expert, expected cost/tokens/quality,
abstention behavior, and fallback. Local-first execution validates before use;
remote shadow disagreement creates learning evidence but not production
authority.

## Corpus, labels, and learning

Each `ResidualDistillationCorpus` row binds example/family/input/context
identities, source/teacher provenance, all teacher alternatives, independent
validation, accepted output, rejected alternatives, counterexamples,
proof/test evidence, repository/language/framework, rights/privacy, and a
semantic-lineage split group. Related repository states, task lineages,
failure/source/procedure/mutant families, and proof obligations stay together.
Hidden tests remain inaccessible; train/holdout leakage is a hard failure.

A strong remote model may nominate but is never ground truth. Labels come from
the type checker, analyzer, test runner, prover, policy/authority/effect
engines, merge result, current-tree receipt, or scoped human reviewer.
Unsupported agreement is preserved as `ambiguous`, `inconclusive`, or
`human_review_required`. Positive examples need exact current identities and
independent validation. Negatives include plausible failures, authority
violations, stale reuse, missing dependencies/validation, unsafe procedure
matches, overconfident non-abstention, prompt injection, test weakening, fake
proof/completion, transfer failures, and assurance mutants.

Active learning combines uncertainty with abstention, disagreement,
validation failure, counterexample novelty, frequency, route impact, token and
human cost. Every acquisition action has a resource and authority budget.
Continual learning is bounded and offline; an epoch binds parent model,
architecture, tokenizer/vocabulary, corpus/split, curriculum/loss/optimizer/
scheduler/seed, environment, code/compiler, and evaluation. Resume preserves
lineage and never implies promotion.

## Runtime, lifecycle, and integration

Existing model serving and live hardware qualification package each expert
with architecture, weights CID, tokenizer, quantization, runtime/operator set,
hardware class, environment, contracts, and evaluation. Quantized artifacts
receive independent evaluation. Compatible requests batch; workers share
immutable artifacts, use bounded queues, and deterministically reclaim
resources. Unavailable local execution yields `capability_unavailable`, never
a simulated answer.

Procedure experts fill declared typed holes under compiler preconditions and
validation. Proof/tactic experts only rank premises, lemmas, tactics, branches,
counterexamples, and failures; the exact current prover obligation and
environment decide. Patch experts emit `PatchSketchIR`,
`ProcedureHoleResolution`, `RefactorOperatorSelection`, or `TestSketchIR` with
exact paths/symbols, line bounds, no test deletion, no validation weakening,
no trusted-key/authority change, isolated worktree, predetermined validation,
and rollback.

Drift covers operation/family/repository changes, calibration, hardware or
quantization, validation regression, abstention collapse, false accepts,
token cost, and procedure/architecture roots. States are `candidate`,
`shadow`, `promoted`, `degraded`, `stale`, `revoked`, `superseded`, and
`rejected`. Stale experts cannot act autonomously; demotion, wider abstention,
shadow-only evaluation, retraining proposals, or revocation are explicit.

The scheduler diagnoses `ready`, `waiting`, `capacity_backoff`,
`capability_unavailable`, `lease_conflict`, and `blocked` separately. A healthy
idle lane requires a current heartbeat plus either no ready work or a typed
bounded backoff. It must not spin, self-complete, exhaust attempts on a known
capacity outage, or report a waiting DAG as blocked.

## Tranches

### Tranche 1: contracts and data (VRIF-000 through VRIF-008)

Seal prerequisites; inventory residual calls; implement strict contracts,
rights admission, first-party/synthetic/adversarial corpus construction,
semantic splits, compact IR, and structured grammars. Focused hermetic tests
run after each bounded task. Training is prohibited.

### Tranche 2: deterministic and small experts (VRIF-009 through VRIF-015)

Implement deterministic/linear baselines, family specifications, grouped
calibration/abstention, OOD/boundaries, the cascade router, first classifiers/
rankers, and one strict structured specialist. If no admitted corpus exists,
training-specific actions return `training_unavailable`; deterministic/runtime
work continues.

### Tranche 3: supervisor integration (VRIF-016 through VRIF-027)

Integrate typed procedure holes, proof/tactic and patch candidates, teacher
disagreement, independent label production, active/offline continual learning,
checkpoint lineage, packaging, batching/serving, drift, and privacy. Reuse
canonical owners and preserve candidate-only semantics.

### Tranche 4: qualification (VRIF-028 through VRIF-032)

Run adversarial assurance, add typed Python/service, CLI and MCP controls,
freeze the paired benchmark, enforce promotion/rollback gates, and generate
current-tree machine/human reports. MCP invokes the typed service directly and
does not shell out to CLI text.

## Promotion gates

Safety/data gates are conjunctions, never weighted averages:

- 100% admitted source/transformation rights and checkpoint lineage; zero
  train/holdout leakage, hidden-test access, or privacy violation;
- zero unauthorized effects, model-created authority/policy/completion,
  simulated-as-live outcomes, stale promotion, critical non-abstention,
  validation reduction, or escaped critical mutant;
- at least 99% precision for eligible low/medium-risk autonomous accepted
  outputs and 100% abstention on known critical boundaries, with no evidence or
  validation reduction; R4/R5 remain proposal-tier;
- against the exact qualified baseline: at least 45% fewer remote-model calls,
  35% fewer model input tokens per accepted criterion, 60% fewer output tokens
  for structured tasks, 50% fewer strong-model calls, and 30% lower median
  residual-decision latency;
- at least 70% eligible classification/ranking coverage, 40% eligible typed
  procedure-hole coverage, and 25% fewer human interventions, with no increase
  in unsafe autonomous mutation; and
- complete training/evaluation cost, per-use saving, expected/observed
  break-even uses, and rollback lineage for each promoted expert.

Threshold changes require current held-out and adversarial evaluation, zero
critical false accepts, authorized CAS, and rollback. A model cannot change its
threshold. One campaign, teacher agreement, confidence, prose quality, model
size, compilation alone, or board completion cannot promote anything.

## Release evidence and rollback

The final machine and human reports bind starting/ending commit and tree,
changed files/symbols, corpus/rights/privacy/splits, architectures/tokenizers/
checkpoint lineage, trained/promoted/rejected experts and boundaries,
calibration/abstention/OOD/adversarial results, calls/tokens/latency/human work
before and after, all costs and break-even, validation/proof coverage,
drift/rollback tests, blockers, eligibility, and rollback target.

No report may claim learned, verified, safe, autonomous, token efficient, or
production ready without exact evidence for that specific claim. Rollback
revokes the candidate or promoted identity by authorized CAS, restores the
previous admitted route/calibration/checkpoint binding, drains fenced work,
and retains failure evidence. Source rollback uses the campaign's exact clean
worktree and merge target; sibling repositories are never modified.
