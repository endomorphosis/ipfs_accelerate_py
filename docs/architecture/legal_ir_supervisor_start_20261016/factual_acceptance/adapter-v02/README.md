# Legal IR source factual acceptance adapter proposal

This isolated source proposal makes independent acceptance of the LIR-9001
engineering report achievable. It does not accept a real report, complete a
task, start a provider, or qualify legal meaning. No product imports or tests
were run while authoring it. AST parsing passed for the six implementation and
test files. The 36 controlled tests await actual native validation.

The predicate derives all 64 tasks, 34 goals, 115 ordered dependency edges,
24 parent crosswalks and 18 frozen files, joins the legacy Markdown fields, and
requires exact source commitments and owner-supplied observation snapshots.
Findings use seven closed codes with exact source roles, JSON pointers and
hashes. Arbitrary model prose and fabricated authority do not satisfy the
criterion. Scope limitations, all 63 blocked future tasks, manual completion,
Grok 4.7 primary and Codex GPT 6.1 Sol high quota-only fallback remain explicit.

The candidate schema is `legal-ir-source-factual-candidate@1`. This is an
explicit proposed report-contract revision, not an undocumented substitution
for the installed `legal-ir-supervisor-handoff-reconciliation/v1`. The installed
bootstrap must retain its closed exit-3 validation command until a reviewed
packet binds this actual host acceptance coordinator. The worker only produces
a candidate; it receives no acceptance handle or status-write capability.

`factual_candidate.py --check-facts` is advisory. `--check-report` remains exit 3
even for valid facts. A file or CLI flag cannot establish independent authority.
The separate controller-only `native_acceptance.issue_native_acceptance` API
uses the exact genuine `ValidationResourceReservation` type, verifies live
VALIDATION/canonical_validation ownership, an actual attached/reaped Popen
child, frozen argv/request/module/input pins, and recomputes the child result.
It calls the genuine seal/finalize APIs and returns a process-local one-use
handle only after verified release. Summaries and durability files are inert.

The same trusted interpreter then obtains a separate actual ORCHESTRATION root
and phase, plus a genuine `ParentedPhaseResourceReservation`. The callable
`controller_coordinator.complete_accepted_legacy_task` verifies actual ancestry,
heartbeats and full public native usage checks, charges the bounded external
board write, and consumes the handle under the existing public legacy board
inode lock. It writes an audit intent, changes only LIR-9001's status, reads back
the exact bytes and writes the outcome event. Every other task remains blocked;
no attempt history is reset. Failed or unknown publication is inspected rather
than replayed with a reconstructed handle.

There is no `LegacyTaskSource` class in the inspected accelerator source. The
public `CanonicalTaskSource.compare_and_swap_status` and `TaskboardStore` CAS
require canonical projection markers absent from this legacy board. The
supported ordinary route uses `locked_taskboard` and
`replace_locked_taskboard`, the same public primitives used by the existing
authoritative-completion fallback when `task_source is None`. This proposal
neither migrates the board to Quack nor invents canonical identities.

`NativeCandidateContext` must come from the trusted actual host dispatch owner:
task identity and exact revision, native attempt, candidate commit/report,
actual provider/model/trigger/outcome receipt, and controller observations.
Worker JSON, another actor's Quack receipt, previous failed attempts, or a
freshly written wrapper receipt cannot establish that origin. The bridge pins
those actual inputs; it does not pretend that hashing arbitrary metadata
authenticates its author. The actual host caller and pinned source import are
part of the reviewed trust boundary.

The 23 fixture files are immutable engineering source exports from accelerator
commit `56890bf656caacb2158ea661bdb4526f5ac5d12c`, totaling 1,052,392 bytes. Their
paths and hashes are in `FIXTURE_PROVENANCE.json`. They are test inputs, not a
provider report or accepted task. The three test modules contain 36 tests plus
mutation subcases. They cover exact graphs/observations, unsupported findings,
JSON type confusion, aliasing, provider policy, native purpose/ancestry,
forged/serialized handles, one-use mechanics, stale board revisions and future
task blocking. Synthetic metadata in controlled tests is never native evidence.

For a genuine admitted test run, redirect all unittest/pytest caches, temporary
files, logs and result descriptors into the actual owned validation layout.
The command is:

```sh
PYTHONPATH=/absolute/path/to/acceptance-adapter python3 -B -m unittest discover -s /absolute/path/to/acceptance-adapter/tests -v
```

This command alone provides no resource admission. The actual native owner
must freeze source/request pins, attach the isolated child before releasing its
startup barrier, monitor real guards, then seal and finalize the result. A
separate finite native integration candidate is needed to exercise actual
issuance, finalization and orchestration publication rather than metadata
doubles. Missing namespace support or native admission must fail closed.

After a genuine provider candidate exists, the root owner can validate it under
this independent native route and publish LIR-9001's factual completion through
the reviewed coordinator. Only a separately reviewed phase projection may then
propose LIR-9002, with an implemented validator of its own. Nothing here admits
teacher/gold data, training, graph semantic fidelity, source-law truth, model
accuracy, a unified Lean corpus, or a successful `lake build legal`.

This V02 changes only the finite handle lifetime from 300 to 900 seconds to
include genuine orchestration admission and repeated native censuses. It adds
explicit expiry/owner refusal tests. Same-process, one-use, nonserializable and
exact source/candidate binding checks are preserved. The original bundle stays
frozen and attributable. No scheduler policy or task attempt cap changes.
