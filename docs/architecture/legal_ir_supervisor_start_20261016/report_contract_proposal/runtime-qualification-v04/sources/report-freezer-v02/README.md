# Report-only candidate freezer successor

This is PI-P03 source code, patches and unexecuted controls. It has not been deployed or run. It creates no task, provider outcome, candidate, native validation handle or completion authority during authoring. The original owned controller and every earlier frozen generation remain unchanged.

The new opt-in `PortalImplementationDaemon.freeze_report_only_candidate(outcome=..., freezer_owner=..., protected_source_sha256=..., declared_external_storage=...)` has no caller-provided task, attempt, baseline, board hash, Git runner or verifier parameter. It invokes the actual successor H `require_active_ordinary_success`, which authenticates the actual outcome only during its original callback. The outcome's callable invocation must be the identical G invocation retained by the actual original daemon launch boundary. Constructing either dataclass, copying an execution UUID, deserializing JSON or recovering a PID cannot establish that join.

The small daemon patch captures the real state/task before the original attempt counter write and captures the original baseline, invocation, workspace and fenced lifecycle after the original launch-boundary state save. The opt-in profile requires both task counters to start at 2, charges only attempt 3 through the original daemon path, keeps the total cap at 3 and preserves every peer counter. It uses the exact original 64-task board bytes as a fixed-SHA trusted input, including the original 0664 mode. Report inputs retain their separate strict 0644 policy; original Git metadata uses a separate stable owned 0644/0664 policy. No original file is chmodded. LIR-9001 remains manual and the other 63 cards remain blocked. Board content itself grants no runtime authority.

The PI-P04 callable bridge is still required. It must pass the original local baseline and identical G invocation, and retain a genuine existing local `duckdb_state.DuckDBConnection` bound to the original state target. PI-P03 never opens a backend or uses the legacy state loader. It refuses absent, closed, poisoned, retired, transactional, catalog-switched or remote/quack connections, then executes only the existing producer's SELECT under that actual connection's execution lock. Its fresh row must match the actual original state/task/attempt/counters. The actual enforcing `DecisionRuntime` must separately authorize the commit boundary. Legacy external CLI callsites lack these retained objects and cannot use this profile.

A fresh genuine ORCHESTRATION freezer owner is a sibling of the provider owner under the same actual phase. It requires exactly 1 CPU, at least 512 MiB and exactly 4 process slots. With the primary's 8 and watchdog's 4 slots, the three owners fit the existing 16-slot envelope. Git children are sequential. Each actual Python start gate is attached through the actual owner before it can exec the pinned Git binary. The group is sampled and refused above 4 processes; each command has bounded output and a deadline, and each group must be empty before return. This is cooperative native admission and sampled enforcement, not a new kernel process quota. Hooks, signing, maintenance, auto-GC, fsmonitor, untracked cache and external diff are disabled; config includes and external clean-filter sections are refused. A failed child cleanup requires retaining native custody.

Private storage must already be charged before the first Git child or lock-file write. The declaration names exactly the minimal containing roots of the original workspace, Git directory and common Git directory. Its ledger key is `storage_charge_key(path)`, its value must match the actual owner's `external_charges`, and each root must be within the actual admitted named roots. Per-root charges are 128–256 MiB, with at most 384 MiB total, a bounded 16,384-entry inventory and 16 MiB growth headroom. Larger, aliased, world-writable, hardlinked, symlinked or unsupported repository layouts refuse; this source proposal does not raise any host storage or process cap.

The lock patch factors the original checkout lock body into `checkout_git_directory_mutation`. The existing public `checkout_git_mutation(repo)` keeps its legacy resolver and behavior. Both entry points share the identical original thread registry, reentrant depth, guard file, flock, foreign-lock refusal and retained-custody refusal. The freezer resolves its directory with an attached actual Git child, then uses the factored original lock, avoiding an unadmitted lookup subprocess.

Within that same lock and original decision mutation callback, the helper verifies the actual HEAD equals the original full baseline, the original branch and board blob are unchanged, no provider commit exists, no hidden index flags/submodules/unmerged entries exist, the index begins clean and no extra dirty, untracked or ignored path exists. The one fixed regular 0644 report must contain an unambiguous JSON object. It checks the index and report preimage, force-adds only that explicit path, verifies the exact single staged report blob and tree, rechecks the active callback, authoritative SELECT row, task/counters/lifecycle/source closure and native admission, then calls the extracted original shared commit tail. The normal generic path still calls that same tail after its own existing staging. The report-only path never calls generic `git add -A`, submodule staging, provider-commit rescue, checkout, reset or merge.

After the commit, the actual object must have exactly the single original baseline parent, exactly the staged tree, exactly one report delta, the unchanged board and exact report blobs, and the current clean HEAD. Every refusal preserves the original attempt, workspace, index and any already-created commit; there is no automatic rollback or repair. The returned dictionary is inert candidate metadata. `validation_passed`, native qualification, acceptance and completion remain false. A separate fresh-owner V03 candidate observation and independent native validation/controller acceptance remain required.

The exact-baseline source assembler writes only proposal patches. It does not apply them. `BASELINE.json` binds both original source files and the exact proposed source bytes; no multi-megabyte daemon copy is included. The 68 authored controls (56 pure controls and 12 source controls) exercise actual 0664 board reading, distinct strict-report/trusted-Git metadata modes, counter preservation, strict JSON and commit/diff/path structures plus actual source call order, original commit argument preservation, exact lock-body reuse, SELECT-only state access, explicit report staging and native gate ordering. They do not mint a positive callback or substitute a fake native owner. Root must qualify them under genuine admission. A later genuine Git component fixture can qualify lock/staging/commit mechanics only; a positive public freezer qualification requires an actual provider callback and the PI-P04 bridge.
