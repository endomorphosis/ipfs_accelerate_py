# Ordinary stopped-cleanup capacity hold

This additive trusted-host helper binds two already acquired, genuine native child leases before Docker/provider effects. Strong process-local references retain the actual objects without a context-manager exit or destructor that could acknowledge their completion. It changes neither the frozen ordinary hook V01 nor scheduler policy, accounting limits, protected74, task status or attempt counters.

The purpose is precise: retain charged capacity when an unknown Docker/kernel closeout reaches an unwary caller's `with` unwind. This is not continued productive authority. Parent/root release, cancellation or expiry revokes ancestry immediately; a retained child's heartbeat cannot restore it. The actual scheduler keeps unacknowledged live-owner descendants charged until their explicit release. Host interpreter death can permit stale recovery to prune all same-process native rows while a daemon-owned container survives, so this helper provides no durable cross-process/death custody guarantee.

## Public API and order

1. Open the genuine ORCHESTRATION root/phase and distinct fresh primary/watchdog `ParentedPhaseResourceReservation` owners. Original hook requirements remain primary1CPU/512MiB/8child slots and watchdog1CPU/256MiB/4child slots, within the actual parent envelope.
2. Before any Docker allocation, use each owner's public `native_lease.acquire_child(cpu_slots=1, memory_mb=1, child_process_slots=0, requires_gpu=False, timeout=FINITE_WAIT, request_id=UNIQUE_CUSTODY_REQUEST)` to obtain the actual native consumers. Zero CPU is unsupported; proof safety also rejects zero memory. Nested children remain inside their parent's existing global allocation.
3. Call `bind_ordinary_custody_hold(primary_owner=..., watchdog_owner=..., primary_consumer=..., watchdog_consumer=..., protected_source_sha256=...)`. The exact source closure is `required_source_paths()`: this helper plus the four held native implementations. The binder checks actual classes/import origins, original owner heartbeat/full usage, fresh process inventories, direct child ancestry, exact existing policy, public consumer renewal and the SDK's redacted live records. It neither creates nor releases a lease. A refusal before effects leaves the caller responsible for its actual unstarted allocations.
4. Keep the opaque returned hold. `observe_ordinary_custody_hold(hold)` separately reports consumer-record presence and cancelled ancestry, with every helper authority flag false. Registry references remain strong even if ordinary owner contexts unwind. They are not portable tokens, file receipts or native credentials.
5. The trusted physical fixture/controller must independently prove the bound actual same-daemon CID/name, captured kernel/PID-namespace/cgroup, both original process groups, watchdog reap, lease root, provider home and prompt are stopped/absent. Unknown state must not acknowledge either consumer. `held_native_consumers(hold)` returns the same actual public objects solely for that trusted stopped closeout; call their public `release()` only after the independent proof. No mapping, bool, report or caller assertion is accepted as cleanup proof by this helper.
6. `forget_acknowledged_custody_hold(hold)` removes registry references only after both actual consumer objects report released and both actual rows are absent. It does not release anything, authenticate Docker cleanup, finalize disk claims or complete tasks. Afterwards the actual owner stopped-cleanup `release(artifacts_durable=True)`/successful `finalize` remains responsible for a fresh census and original process-group death. No private ledger writes or reconstructed lease keys are used.

The first generation implements the capacity barrier and observation, not a full automatic stopped-cleanup handler. It deliberately exposes the original actual consumer references for a separately qualified trusted fixture's closeout. The native fixture must test that owner finalization/refuse-forget cannot bypass live consumers, that unknown state remains charged, and that independently proven cleanup allows explicit public consumer release followed by actual row drain. It must not infer Docker/kernel closure from a lease flag or serialized receipt.
