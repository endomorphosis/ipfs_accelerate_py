# Report-only candidate freezer: upstream integration requirements

The ordinary daemon already has the Git candidate producer needed for Legal IR. A standalone adapter cannot yet call it truthfully: its producer is private and follows successful declared validation, while this report contract deliberately keeps advisory `--check-report` at exit3 until a separate native one-use acceptance handle exists. Freezing the candidate must precede native validation of that candidate. Wiring the existing validation-success branch directly to the new native backend would therefore leave a commit/validation cycle.

This directory contains a source review and actionable hook tasks. It creates no candidate, dispatches no provider, changes no retry counter or board, constructs no `NativeCandidateContext`, and issues no acceptance. There is intentionally no callable effectful freezer. The ordinary route does not currently expose a public, genuine same-process successful provider-outcome capability. An inert receipt, historical event, PID or caller-supplied success flag cannot fill that gap.
