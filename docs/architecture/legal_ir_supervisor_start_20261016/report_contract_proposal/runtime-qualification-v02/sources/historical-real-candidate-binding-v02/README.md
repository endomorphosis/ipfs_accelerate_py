# Candidate binding observer V02

V01 could never observe a real candidate with the current trusted source closure: its implementation-pin check reused the private candidate reader, which rejects group-writable files. The frozen observer, deployed daemon and held native parented-owner implementation are all owned mode0664. Exact source pins therefore failed before real Git observation. V02 fixes this reader mismatch without changing or chmodding frozen/shared sources.

`read_pinned_source(path, expected_sha256)` accepts a stable regular implementation file owned by root or the current user, with one link and no world-write permission, only when its bytes match the required exact SHA256. Canonical unaliased paths, bounded reads and before/after/final-path identity checks remain mandatory. The stable witness now also includes mode, owner, group and link count, so permission/ownership changes during a read refuse even when content is unchanged.

`read_regular(path)` remains the strict private candidate reader: group/world-writable board or report files still refuse. Candidate qualification fixtures must be written/fsynced mode0644 under actual separate preparation ownership. The successor does not permit a caller to weaken this policy. Native ownership, task parser correspondence, ten attached finite Git children, exact single baseline parent, clean worktree, report-only diff, exact Git blobs and the64-task closed frontier are unchanged. `observe_real_candidate_binding` still requires a genuine fresh same-process parented ORCHESTRATION owner and returns inert observations only.

The output schema advances to `legal-ir-real-candidate-binding-observation@2` and records both reader policies. All authority flags remain false. This observer cannot authenticate provider success, create a commit, dispatch a provider, mint/consume acceptance, update a board, reset attempts, qualify training, or establish legal/proof fidelity. The ordinary route still needs a genuine host fenced-provider-outcome hook, a supported report-only candidate freezer and real native-validator/controller integration. No backend stub or accepting flag is added.
