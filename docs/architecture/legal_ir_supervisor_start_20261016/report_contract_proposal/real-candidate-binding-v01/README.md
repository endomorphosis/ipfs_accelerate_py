# Trusted real candidate binding observer proposal

This additive source-only module closes one host-observation gap: it checks that the actual current Git candidate has exactly the declared baseline parent, changes only the declared LIR-9001 report, and contains the exact observed report and board bytes. It never creates a commit, materializes a packet, dispatches a provider, constructs `NativeCandidateContext`, issues acceptance, completes a task or changes an attempt counter. Adapter V02, the frozen packet and V04 remain unchanged.

`observe_real_candidate_binding` requires a fresh, actual same-process `ParentedPhaseResourceReservation` in ORCHESTRATION, with at least one CPU slot, 512 MiB and one child slot. The genuine public owner verifies its native ancestry, heartbeat, active status and full named-root accounting. The root supplies exact SHA256 pins for this observer, the actual deployed daemon/public identity implementation, four held native SDK implementations, Python and Git. The observer checks these pins before product imports and again before return. Cold import uses only the standard library and performs no writes.

The public callable accepts the actual owned isolated repository root, exact board path, pinned baseline and candidate commit IDs, exact board/report SHA256, and protected source pins. The candidate must be current HEAD, have exactly one parent equal to baseline, and change exactly the fixed report path. JSON report and board entries must have mode100644 and type blob. Both actual Git blobs must equal the safely read regular source files; the diff must independently bind the report blob. The worktree must be clean. HEAD, source pins, board and report are checked again before returning. Expected IDs are correspondence pins and cannot supply the missing observations themselves. The caller must prepare a report-only commit under separate authorized ownership first; this observer cannot do that work.

The observer uses the actual deployed public `parse_task_text`, `task_declared_output_paths` and `canonical_task_identity` functions. It rejects caller-provided canonical identity shortcuts and duplicate task metadata before parsing. It requires the original64 task aliases, LIR-9001 todo/manual and the other63 blocked. The real observer defines `task_revision` as the parser-derived canonical task CID, matching ordinary daemon `_canonical_ref` for the actual LIR-9001 board, whose additional Allowed paths field is absent. A nonempty LIR-9001 Allowed paths field is explicitly refused: the daemon wraps provided parser identity with that additional authority, requiring a distinct revision convention. Exact board byte revision is separately returned as both `board_sha256` and `expected_board_sha256`, the latter for a later controller request. Thus instruction-only board changes can preserve semantic CID while still invalidating byte-level controller CAS. V04's historical synthetic fixture uses a board hash for its context revision; this proposal does not silently change or generalize that fixture convention.

Ten actual read-only Git observations run as sequential direct children of the genuine owner. Each starts an isolated process group behind a fixed stdin gate, is attached through public `check_usage(..., child_pid=...)`, and cannot exec Git until attachment and heartbeat pass. The fixed trusted barrier waits at most180 seconds and sets CPU15s, address-space256 MiB, output-file0 and descriptor64 limits before exec. Git has a 15-second productive deadline, bounded stdout/stderr and actual sampled group checks. There is no per-UID process-limit claim or kernel combined-RSS claim. The child environment is explicitly constructed; inherited Git variables, global/system config, hooks, fsmonitor, optional locks, lazy fetching, replacement objects and external diff are disabled. The exact root owns and trusts the repository's existing Git metadata/configuration; these read-only commands are not an untrusted-repository sandbox. Cleanup can stop only the still-running direct child group; an unknown or nonquiescent descendant remains a genuine owner's closeout responsibility. No observer artifact is written, and the caller separately charges any durable output.

The returned schema is `legal-ir-real-candidate-binding-observation@1`. It includes real task CID/key/revision, exact board/report bindings, parent/tree/current HEAD, source pins and a redacted actual owner identity. It is inert metadata. Every authority flag is false, including provider-outcome observation and native-validation qualification. Serializing this result cannot mint a native owner or one-use acceptance handle. A later trusted integration must independently observe the real dispatch/provider route, attempt ordinal, PID birth and fenced successful closeout; it must not infer those facts from this report, a historical receipt or a PID alone.
