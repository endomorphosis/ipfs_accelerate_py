## Next native controls

The next native increment must test effects after an actual child exists. The
retained [control design](../../../../artifacts/codebase_ir_terminal_bench/finite-proof-query-attempt-lease-native-20261004-01/negative-native-control-design-01/review.json)
is preparation only. It identifies three distinct controls:

1. Let the genuine native transaction callback receive an actual kernel birth
   acknowledgement, retain that birth and an external marker, then deliberately
   raise before the enclosing native guard can commit. The SQL rollback does
   not remove the process or external marker. Publication must be refused,
   the uncertainty retained, and the original process group plus isolated UID
   cleanup proved complete before closing runtime cleanup/resource obligations.
   A failed callback releases the native transaction lock before client cleanup;
   rollback is not proof that external effects or children have disappeared.
2. Receive a genuine spawned ACK frame from the actual launcher and retain its
   separately checked kernel identity, then deliberately drop it before broker
   validation. This is a transport/application-drop fixture. The broker may
   correctly retain an unknown birth while fixture evidence establishes an
   actual child. Neither the coordinator nor the clock may be substituted.
3. Shorten the genuine renewable attempt lease before the guard and use the
   real deadline to exercise expiry after actual ACK. It must pass the same
   pre-send budget rule and then refuse an expired post-check without relying
   on a fake clock or same-thread authority reentry.

Each fixture must retain its full closed execution ledger before deriving any
smaller summary. Existing pre-birth helpers assume a particular early task
revision and empty effect rows; they cannot be reused to discard post-birth
provider activity, committed effects or worktree edits. A committed receipt
cannot be rewritten as a failed no-effect receipt. Publication refusal,
logical noncompletion, actual effect uncertainty and cleanup are separate
joins. The present positive run and earlier 128-case host qualification do not
close these native negative-control exits.

The new scheduler observation provides future refusal diagnostics without
changing the original admission thresholds. A later captured native profile
must exercise these new bytes before claiming native integration. Historical
failed runs have no numeric failure-time PSI sample; new diagnostics cannot
retroactively supply one.

## Resolve intent against current code

The current finite profile supplies one checked entry, five exact proof keys
and 89 normalized dependencies. Generalize the existing interfaces only after
the repository evidence owner can return an exact, complete population:

| Boundary | Required retained material | Refusal or recovery condition |
| --- | --- | --- |
| Prompt to IntentIR | Original prompt digest; typed clauses with provenance; positive, negative and unresolved requirement coverage; supported property profile | Refuse to silently omit a clause or invent its semantics. Preserve unsupported requirements as residual obligations. |
| IntentIR to current CodebaseIR | Exact repository head/generation and source-unit IDs; symbol, type, call and effect bindings; source-correspondence receipt for the chosen profile | A nearest vector or autoencoder reconstruction nominates a unit; it does not establish intent satisfaction. Stale head or unmatched requirement remains unresolved. |
| Proof-index lookup | Complete typed query population under snapshot, profile, environment/tool/premise/model and evidence-policy keys; root-bound page cursor and explicit omissions | Partial, stale or differently keyed evidence cannot become a fact. Independent cold replay must reproduce the exact consumed population. |
| Symbolic plan to native action | Material digest; facts and residuals; proposed action contracts; signed native admission; live claim, lease, attempt and fences through ACK | Refuse changed source/evidence or expired authority; retain uncertain effects and finish cleanup. Planning facts do not supply mutation or completion authority. |

The public service must consume the same current source/evidence roots in
preview, admission and execution. The finite entry point does not establish
complete public prompt coverage, unrestricted source semantics or automatic
Harbor/Terminal Bench routing. Full task and proof populations, cached private
presentation completeness and expired-policy STOP remain separate gates.

## Hydrate recoverable repository metadata

Capture a source inventory before fitting. Every unit records exact source
bytes, path/span, parser and extraction profile, diagnostics and unsupported
features. Normalize AST/symbol/type, CFG/dataflow/effect, call graph/KG, vector
lineage, contracts, domains, assumptions, obligations and evidence provenance
under one generation. Store actual row and omission counts for every family;
a fixture's five proof keys cannot stand for this population.

Publish through the existing DuckDB native owners with a durable DuckLake
outbox. Prove idempotent replay of the same generation, interruption before and
after each publication boundary, and recovery without mixed-generation rows.
Retention must keep replayable metadata and pinned source/model/proof receipts.
An edit computes reverse dependencies, invalidates affected evidence and
training material, and compares the complete incremental successor with a
fresh cold scan. Search nominations and proof-cache reuse remain distinct.

## Adapt a private repository model

On-demand training is private to the tested repository generation and the
existing shared resource owner. Pin tokenizer/extractor/runtime, feature schema,
initial weights and training corpus; reserve training, inference and checkpoint
costs explicitly. Retain the optimizer, sampler, RNG and cursor state needed
for exact interruption/resume. Keep the holdout population fixed before
training and prevent task solutions, proofs or evaluation outputs from leaking
into training examples.

Decode learned candidates into typed CodebaseIR with source-unit provenance.
Admission of a candidate formula requires independent source correspondence
and the appropriate checker. Promotion compares frozen versus adapted models
under a predeclared evaluation policy and publishes through a generation-bound
compare-and-swap. Failure keeps the previous checkpoint and planning fallback.
The MODEL_OFF native run supplies no newly trained codebase model; a native
provider invocation is not an inference counter. Broader fit and dense/model
invocation counts remain unknown without actual instrumentation.

## Logic projections and convergence

For every supported FOL/SMT, temporal, CEC/DCEC or other logic projection,
declare grammar, sorts, domains, state/fairness assumptions and unsupported
constructs. Retain the exact translation receipt and an independently checked
source correspondence. Lean must compile the recorded theorem and premises
without `sorry` or unreviewed axioms. Different family names or successful
compilation do not establish equivalent semantics; cross-family correspondence
requires its own checked obligation.

Start the convergence gate with the declared fixed-feature regularized decoder
and an update rule whose assumptions can actually be checked. Retain the
matrix/spectral bounds, step size, initialization, loss definition and finite
precision error bound; prove the stated rate in Lean and compare every
retained numerical iterate against that bound. An empirical loss decrease,
autoencoder reconstruction score or the finite arithmetic certificate from
this worker fixture cannot prove general nonlinear or Adam convergence.

Matched official benchmark arms then compare MODEL_OFF, frozen and adapted
profiles on the same task population and source roots, with cold/warm/edited
successors, actual training/proof/inference costs, failed attempts, omissions
and cleanup. These higher exits remain open.
